# 剪贴板历史的只读检查与人工恢复

`inspect-clipboard-history.mjs` 检查明确指定的本项目纯文本历史文件。它不推断配置位置、不运行应用或监听器、不读取系统剪贴板，不创建写锁，也不清理、覆盖、重排内容或重置 ID。

```powershell
node tools/script-sdk-check/inspect-clipboard-history.mjs --file '<绝对历史文件路径>'
node tools/script-sdk-check/inspect-clipboard-history.mjs --file '<绝对历史文件路径>' --scan-temporaries
```

必须替换为明确的本地绝对文件路径。没有默认路径，也不会自动查找个人配置。工具仅向 stdout 输出 JSON；不会写报告文件。退出码 0 表示完成普通观察或显示帮助，2 表示存在需要处理的发现、无法观察或参数错误；这个退出码不代表某次历史动作已经失败或可以重试。

## 报告范围

- `history` 只含版本、字节数、项目数量、UTF16 总量、规范 ID/revision 和固定错误原因。不输出正文、摘要预览、正文哈希或 JSON 异常片段。
- `lock` 检查显式文件同名 `.lock` 的完整字节标记。`fresh` 表示标记为 0，`initialized` 表示为 1。锁文件存在、标记为 0 或文件名中的 PID 都不能证明当前没有写入者。
- 默认不枚举临时文件。显式 `--scan-temporaries` 只在该文件的直接父目录中，检查 `<历史文件名>.<PID>.<nonce>.tmp` 的候选；最多枚举 1000 个目录项、读取 8 个候选，不递归，不读取其他名称的文件。`complete=false` 表示观察不完整，不能视作没有其他候选。
- 每个正文或候选读取上限 8 MiB；拒绝非 UTF8、BOM、重复字段、未知字段、非规范版本/计数、无效 Unicode、NUL、错误顺序和容量超限。格式按当前写入器的规范版本 1 对象校验；该检查工具不是另一种导入格式或修复器。
- 读取前拒绝云盘名称、Windows Offline/Recall/Reparse 属性、符号链接/联接点及多链接普通文件。通过文件句柄前后元数据与路径身份比较检查读取期间变化；不跟随链接或绕过占位保护。
- `disk.availableBytes` 只是当前同一文件系统可用空间的只读观察。`lessThanMaximumTemporary=true` 提醒可用空间不足 8 MiB，不能证明之前磁盘满、下一次写入必定失败或当前文件已经损坏。文件系统无法提供信息时报告 `unavailable`，不做试写。

整个报告是 `unlocked_observation`，`writerLiveness=unknown`。工具没有获得 Store 写锁，不能证明正文、锁和多个候选来自同一事务，也不能保证抵御不合作进程在检查之间更换路径。

## 磁盘满或写入失败

应用先准备同目录临时文件、写入并同步、关闭句柄，比较旧文件字节，再替换正文。准备阶段正常报错时会尝试清理本次临时文件；进程中止、断电、清理失败或权限变化可能留下文件。

1. 先停止新的历史追加/删除及显式观察工作，等待在途调用结束。工具不会替你停止应用、线程或进程；不要根据 `.lock` 存在与否猜测所有写入者已退出。
2. 在任何人工修改前，将正文、sidecar 及待审查候选保留到另一个明确的私有备份位置，保留原字节与相关文件元数据。备份同样含私有正文，访问权限应至少同样严格。检查工具本身不执行备份或修改。
3. 用上述显式路径检查当前文件。若磁盘空间不足，处理已经明确归属、可释放的其他数据；不要把自动删除历史或候选作为腾空间步骤。更新时可能同时存在旧正文与最多 8 MiB 的新临时文件，还需要文件系统元数据空间；可用空间达到这个数也不构成持久化保证。
4. `effectState=not_started` 表示这次写入尚未提交；`unknown` 表示不能据错误断言未提交。替换或替换后的锁标记同步失败、提交后的取消都可能是 `unknown`，禁止自动重试。
5. 当前正文仍合法，只说明当前快照结构正常。仅凭 revision 变化或临时文件存在，不能确认某次未知效果的追加是否已提交；其他写入者也可能增加 revision。确需判断时，应由应用中明确授权的读取流程核对对应项目，正文不应粘到终端日志。

工具不能从当前自由空间倒推历史失败原因，也不保证任意断电下的磁盘持久化。

## 进程中止后的临时文件

候选文件名中的 PID 可能已复用，完整 JSON 也可能只是尚未提交的准备结果。部分候选可能为空、截断、版本未知或不可读取。这些情况只形成证据，不构成自动提升候选的依据。

在已停止所有写入者、保存证据后，可以人工核对已知备份、原有 ID/revision、容量、当前正文和候选来源。不要按“最新修改时间”“最大 revision”或“完整 JSON”直接把候选改名为正文；它们不能证明那次动作已经提交或候选属于当前历史。后续删除任何已审查遗留文件也应另行明确决定，工具不会执行。

## 正文或锁异常

| 观察 | 处理原则 |
| --- | --- |
| 正文合法，锁正常，有候选 | 保持正文；候选在停止写入者并备份后人工审查。 |
| 正文缺失，锁为 initialized | 保留 sidecar，保持阻断，不创建空历史。它证明之前观察或提交过正文，不能默默从 ID 1 开始。 |
| 正文损坏或超限 | 保留原字节，不截断、trim、重新序列化或用空对象覆盖。先检查是否观察期间发生变化，再核对可信备份。 |
| 锁未知、截断或不可读 | 保留原锁；不要自动删除或重建。写入者仍持有旧句柄时删除锁会破坏实例间协调。 |
| `changed_during_read` | 当前观察无效；先停止写入者，再明确发起一次新的只读检查，不把它解释成确定的文件损坏。 |
| 属性、链接、权限或父目录拒绝 | 先处理明确路径本身；不要用跟随链接、移动到云盘或换工具读正文来绕过保护。 |

人工恢复必须维持已经发放 ID 的不复用，以及 revision 单调语义。已删除项目的 ID 也不能复用，不能从当前 `items` 最大 ID 推算 `lastId`。当前 sidecar 只有初始化标记，没有完整的计数高水位；较旧备份或临时文件本身不能证明覆盖所有已发放 ID。缺少可信的完整计数证据时应保持阻断，不能通过重置字段“修好”。工具没有自动回滚或恢复命令。

## 合成测试

```powershell
node --check tools/script-sdk-check/inspect-clipboard-history.mjs
node --test tests/clipboard_history_inspector.test.mjs
```

测试只在项目 `.tmp/history-inspector-synthetic-*` 新建目录中写合成文件，核对检查前后字节与文件名单不变，验证脱敏、损坏 JSON、容量、标记、扫描上限和路径拒绝。不会制造真实磁盘满、终止应用或访问个人历史。
