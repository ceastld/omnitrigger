# 输入语义与边界

本页说明 OmniTrigger 如何解释前缀、组合、长按、快速拖拽与滚轮，以及哪些行为受 Windows 与硬件限制。“任意组合”是模型的扩展目标，实际能力受系统与硬件提供的事件约束。

## 统一的触发描述

录制器生成 `TriggerSpec`，注册、冲突检查与运行时匹配共享这一份语义。核心按 `InputEvent + 显式时间与上下文 → Engine::process_at / advance_time → Decision` 工作，鼠标位置、屏幕矩形和前台进程名由平台显式提供，输出透传、消费、触发通知及必要的补发计划。核心不读取系统时钟，不依赖 UI 或 Windows API，相同输入可以重放验证。模块划分见[工程架构](ARCHITECTURE.md)。

## 前缀暂存与回放

普通前缀按下时暂存输入，组合命中后消费整次按压；遇到不匹配输入或单独松开时回放。专用键盘层使用 `keyboard.dedicated_prefix`，不回放专用键自身，也消费层内未匹配的键盘按压。鼠标透传、失败前缀和滚轮余量分别保留收尾语义。延迟与补发会改变时序，不能承诺完全无损。前台窗口切换、暂停或替换注册列表时取消旧缓冲，避免向新窗口补发旧输入。

## 组合、重复与滚轮

组合默认使用精确按下集合，区分左右修饰键；键盘按住默认只触发一次，可用 `keyboard.repeat` 为键盘按下触发显式启用重复。精确模式每次重复事件至多触发原动作一次；显式捕获模式按当前捕获集合重新选择。滚轮以 Windows 标准的 120 增量为一格，高精度增量累积，正反方向分别统计。自身补发和其他软件注入不触发，也不参与录制。专用层和重复的完整配置见[键盘策略](CONFIGURATION.md#专用键盘层与按住重复)。

本版支持“按住若干键 + 按下一键/滚轮方向”、目标键长按及鼠标快速拖拽，可分别附加一个鼠标位置条件，最多 512 条绑定、每条最多 8 个前缀。

每条绑定还可配置应用范围 `process_scope`。指定应用的规则优先于同组合的全局回退；进程未知时不猜测回退，前台变化会取消旧按压、计时及滚轮余量。进程匹配在上下文更新时预先计算，Hook 匹配不查询映像路径。配置和未知状态的具体行为见[应用范围](CONFIGURATION.md#触发器的应用范围)。

精确模式中，同一个键可在不同组合中分别担任末键和前缀。例如 `CapsLock+Space+E` 与 `CapsLock+E+P` 可共存，因为按住的前缀集合不同；配置见[可区分的末键与前缀示例](../examples/terminal-prefix-contexts.json)。一次按压被认领为动作末键后（包括等待长按或快拖），必须先松开再按下，才能成为其他动作的前缀；松开 Space、自动重复或注入的释放都不能转借这次 E 按压。原动作允许重复时仍只重复原动作。

`keyboard.matching.kind=captured` 显式使用捕获集合：未命中动作的附加键才被捕获，无附加键的默认规则可在额外附加键按住时匹配，未识别的键和旧末键不进入该集合。指定应用优先，再按显式顺序选择。动作先于捕获，因此“末键兼附加键”的规则可共存，但先命中动作的按压不会自动成为前缀。配置、重复及结束条件见[捕获集合匹配](CONFIGURATION.md#捕获集合匹配)。

## 鼠标修饰键观察

版本 18 的 `keyboard.matching.kind=mouse_exact` 用于鼠标按下或滚轮，`held` 可为空或一个修饰键。泛型 Shift、Ctrl、Alt（VK 16、17、18）接受左侧、右侧或双侧同时按住；明确侧别的键仍只匹配该侧。修饰键的按下、重复和释放照常交给应用，不作为暂存前缀；其他按住键或鼠标键会排除匹配。空 `held` 要求没有其他物理按住输入，不能将它理解为仅排除修饰键。

这项策略目前通过配置和 API 提供，录制不会自动把具体侧键改成泛型。它不能混用专用层、保留原功能层、捕获集合或重复策略，也不用于长按和快拖；注册时对相交的泛型／具体侧组合及观察／捕获交付冲突返回结构化错误。不足一格滚轮在修饰键释放、额外按压或离开区域时按既有补发规则收尾，不承诺无损恢复；取消仍按原契约丢弃待定输入。

匹配只使用平台已经提供的标准化事件，不补采样系统全局按键状态。严格排除全部额外按住输入，也不等同于其他程序只排除其已捕获输入的策略。

## 长按与快速拖拽

长按阈值为 50–10000ms，同一按压只触发一次；计时不依赖下一次输入。快速拖拽使用 `TriggerSpec` 的 `Activation::Drag`，可配置 4–500 个物理像素及 20–2000ms 的严格起步时窗；预设为 `18px / <180ms`，不绑定特定动作。

鼠标长按单独等待时，尚未到时位移超过 8px 会取消；与快拖共存时，快拖时窗内的 9px 小位移不会提前补发。快拖到期仍静止则继续等待长按；同次按压命中其中一项后不再触发另一项。额外按键、滚轮、切窗、暂停、录制和替换绑定会取消相应等待或拖拽会话，必要的释放收尾继续处理。右键短按或快拖失败后的补发会改变原始输入时序与拖动起点，不能承诺无损恢复；系统调度也会影响浮窗实际显示时刻。参数与诊断见[触发预设、长按与快拖](TRIGGER_PRESETS.md)。

## 冲突规则

同优先级下，重复组合、普通按下与同组合的长按或快拖争用、同一组合配置多个长按或多个快拖会返回冲突；应用范围或位置条件可证明互斥时允许分别绑定。指定应用规则与全局回退可共存，优先级在按下时选定，普通按下不会抢先执行较低优先级的回退。同组合的一个长按与一个快拖可以共存，但同优先级下快拖时窗必须严格短于长按阈值。末键同时被其他组合用作前缀，且其动作所需的全部前缀也包含在另一组合的前缀中时，会抢先触发或预留末键，仍返回冲突；例如 `CapsLock+E` 与 `CapsLock+E+P`。只有应用或位置范围互斥才能消除这类冲突，不能仅靠优先级。界面禁止不限位置的裸左/右键“按下即触发”；可明确选择区域条件、长按或快拖。

## 尚不支持与系统限制

暂不支持双击、多击、顺序连击或按设备区分；Windows 安全桌面和系统保留组合仍受系统限制。

普通权限运行；向权限更高的应用补发输入可能失败，此时暂停监听并显示错误。无需安装驱动。其他软件在上游拦截输入时的表现见[并用其他工具与诊断](TROUBLESHOOTING.md)。
