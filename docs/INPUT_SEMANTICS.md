# 输入语义与边界

本页说明 OmniTrigger 如何解释前缀、组合、长按、快速拖拽与滚轮，以及哪些行为受 Windows 与硬件限制。“任意组合”是模型的扩展目标，实际能力受系统与硬件提供的事件约束。

## 统一的触发描述

录制器生成 `TriggerSpec`，注册、冲突检查与运行时匹配共享这一份语义。核心按 `InputEvent + 显式时间与上下文 → Engine::process_at / advance_time → Decision` 工作，鼠标位置、屏幕矩形和前台进程名由平台显式提供，输出透传、消费、触发通知及必要的补发计划。核心不读取系统时钟，不依赖 UI 或 Windows API，相同输入可以重放验证。模块划分见[工程架构](ARCHITECTURE.md)。

## 前缀暂存与回放

普通前缀按下时暂存输入，组合命中后消费整次按压；遇到不匹配输入或单独松开时回放。专用键盘层使用 `keyboard.dedicated_prefix`，不回放专用键自身，也消费层内未匹配的键盘按压。鼠标透传、失败前缀和滚轮余量分别保留收尾语义。延迟与补发会改变时序，不能承诺完全无损。前台窗口切换、暂停或替换注册列表时取消旧缓冲，避免向新窗口补发旧输入。

## 组合、重复与滚轮

组合默认使用精确按下集合，区分左右修饰键；键盘按住默认只触发一次，可用 `keyboard.repeat` 为键盘按下触发显式启用重复。精确模式每次重复事件至多触发原动作一次；显式捕获模式按当前捕获集合重新选择。滚轮以 Windows 标准的 120 增量为一格，高精度增量累积，正反方向分别统计。自身补发和其他软件注入不触发，也不参与录制。专用层和重复的完整配置见[键盘策略](CONFIGURATION.md#专用键盘层与按住重复)。

本版支持“按住若干键 + 按下一键/滚轮方向”、目标键长按及鼠标快速拖拽，可分别附加一个鼠标位置条件，最多 512 条绑定、每条最多 8 个前缀。

每条绑定还可配置应用范围 `process_scope`。指定应用的规则优先于同组合的全局回退；进程未知时不猜测回退，前台变化会取消旧按压、计时及滚轮余量。进程匹配在上下文更新时预先计算，Hook 匹配不查询映像路径。配置和未知状态的具体行为见[应用范围](CONFIGURATION.md#触发器的应用范围)。

精确模式中，同一个键可在不同组合中分别担任末键和前缀。例如 `CapsLock+Space+E` 与 `CapsLock+E+P` 可共存，因为按住的前缀集合不同；配置见[可区分的末键与前缀示例](../examples/terminal-prefix-contexts.json)。一次按压被认领为动作末键后（包括等待长按或快拖），必须先松开再按下，才能成为其他动作的前缀；松开 Space、自动重复或注入的释放都不能转借这次 E 按压。原动作允许重复时仍只重复原动作。

`keyboard.matching.kind=captured` 显式使用捕获集合：未命中动作的附加键才被捕获，无附加键的默认规则可在额外附加键按住时匹配，未识别的键和旧末键不进入该集合。指定应用优先，再按显式顺序选择。动作先于捕获，因此“末键兼附加键”的规则可共存，但先命中动作的按压不会自动成为前缀。配置、重复及结束条件见[捕获集合匹配](CONFIGURATION.md#捕获集合匹配)。

## 监听流的小增量门禁

开发入口可为本次监听流显式选择 `--wheel-input-policy small-vertical-150ms`。不传参数或指定 `unfiltered` 时保留普通行为；策略不保存进绑定，也不修改录制得到的 `TriggerSpec`。完整重建监听会开始新的门禁历史，暂停、切窗或替换绑定不会清空间隔。

```powershell
omnitrigger.exe --wheel-input-policy small-vertical-150ms
omnitrigger.exe --smoke-test --wheel-input-policy small-vertical-150ms
```

在没有活动鼠标会话时，垂直滚轮增量严格位于 `-10 < delta < 10` 的包共用 150ms 门禁。距离上一次放行的小包不足 150ms 时，该包直接交还系统，不进入匹配器，不消费、不补发，也不取消引擎里的等待或推进引擎时间；被门禁排除的包不延长间隔。放行时在规则匹配之前更新历史，因此未命中区域的小包也会影响下一次小包。上下方向、位置和规则共用同一份历史；水平滚轮及绝对值至少 10 的包不更新它，也不通过累积小包来凑阈值。

会话快照由核心捕获的鼠标前缀和鼠标拖拽生命周期产生，普通物理按住、观察并透传的左键前缀、键盘层、已经作为普通末键的按压或正在收尾的按压不能代替该身份。当前注册模型只允许鼠标终键拖拽，没有可建立的纯键盘键加移动会话；不能把带键盘前缀的鼠标拖拽描述成这种能力。

平台用系统运行时间给门禁传入独立的绝对毫秒，核心仍由调用者显式提供时间。门禁在注入过滤之前观察轮包，因此被后续忽略的注入也可能影响间隔；它们继续不触发、不参与录制。录制保留原始物理包，`Packet`、`Notch` 与触发描述的含义不变。策略作用于整条监听输入流，不能按单条绑定、方向或应用分别计时。

该参数只用于启动监听及 Hook 烟测；与配置检查、动作执行等无监听操作混用会在操作前结构化拒绝。它不会自动启用个人迁移配置。核心被借用时的回调仍保留原有透传行为，不递归执行匹配；独立门禁会观察滚轮历史并记录诊断计数，但不保证这类物理重入仍能完成录制或按压收尾。输入序列测试与 Hook 安装清理不代表真实物理滚轮、其他软件或所有设备均已验收。

## 鼠标快捷键的忙时投递

开发入口 `--mouse-shortcut-queue <计划文件>` 可为一组已有的鼠标快捷键绑定选择共享投递策略。只支持鼠标按下或滚轮触发的 `SendShortcut`；绑定仍须启用并满足原触发范围。未传此参数时保持原投递方式，不读取计划文件。

计划中的 ID 必须来自本次 `--config` 所选配置。例如：

```json
{"bindings":[71,72],"policy":{"kind":"delay","capacity":2,"max_submit_wait_ms":100}}
```

`delay` 按 FIFO 保存至多 1–64 个等待项，投递等待预算为 1–60000 毫秒；预算截至提交给快捷键执行器，不限制执行器内部等待或系统输入耗时。每项保留本次触发捕获的原目标、按键与时序，不重新抓取前台。也可显式采用 `{"bindings":[71],"policy":{"kind":"drop"}}`，在前一项仍等待、运行或终态尚未消费时拒绝新项。队列满或等待过期均不重试。

```powershell
omnitrigger.exe --config .\bindings.json --mouse-shortcut-queue .\mouse-queue.json --check-config
omnitrigger.exe --config .\bindings.json --mouse-shortcut-queue .\mouse-queue.json
```

计划最多 16 KiB，未知字段、重复字段、重复或不存在的绑定 ID、非法范围均明确拒绝。普通启动可附加 `--panel`；不能与历史窗口、动作运行、烟测或其他操作模式混用，暂不与 `--wheel-input-policy` 组合。暂停、录制、替换配置或取消会撤销相应等待项；已经提交的调用只请求取消，收到对应调用的明确终态后才释放占用。未知结果保留占用，不推断成功或重复发送。此策略只调度动作，不改变 Hook 的消费、释放或补发语义。

## 鼠标修饰键观察

版本 18 的 `keyboard.matching.kind=mouse_exact` 用于鼠标按下或滚轮，`held` 可为空或一个修饰键。泛型 Shift、Ctrl、Alt（VK 16、17、18）接受左侧、右侧或双侧同时按住；明确侧别的键仍只匹配该侧。修饰键的按下、重复和释放照常交给应用，不作为暂存前缀；其他按住键或鼠标键会排除匹配。空 `held` 要求没有其他物理按住输入，不能将它理解为仅排除修饰键。

这项策略目前通过配置和 API 提供，录制不会自动把具体侧键改成泛型。它不能混用专用层、保留原功能层、捕获集合或重复策略，也不用于长按和快拖；注册时对相交的泛型／具体侧组合及观察／捕获交付冲突返回结构化错误。不足一格滚轮在修饰键释放、额外按压或离开区域时按既有补发规则收尾，不承诺无损恢复；取消仍按原契约丢弃待定输入。

匹配只使用平台已经提供的标准化事件，不补采样系统全局按键状态。严格排除全部额外按住输入，也不等同于其他程序只排除其已捕获输入的策略。

## 无 Ctrl/Shift/Alt 的鼠标透传观察

版本 22 的 `keyboard.matching.kind=mouse_unmodified` 只支持空 `held` 的鼠标按下或滚轮。普通键、Win 键与额外鼠标键只有在仍按原样透传时才可同时存在；Ctrl、Shift、Alt 的泛型、左侧或右侧任一个按住都会阻止匹配。暂存、已消费、被会话引用或等待收尾的按压不能借来触发。此规则只消费自己命中的鼠标末键或滚轮，不改变其他键的按下、重复或释放。

这一判断来自显式输入事件与核心记录的所有权，不查询隐藏的全局键盘状态。注入过滤、应用和位置范围、取消及已消费释放的收尾继续使用统一规则。配置、优先级与停用示例见[配置说明](CONFIGURATION.md#版本与备份)。

## 长按与快速拖拽

长按阈值为 50–10000ms，同一按压只触发一次；计时不依赖下一次输入。快速拖拽使用 `TriggerSpec` 的 `Activation::Drag`，可配置 4–500 个物理像素及 20–2000ms 的严格起步时窗；预设为 `18px / <180ms`，不绑定特定动作。

鼠标长按单独等待时，尚未到时位移超过 8px 会取消；与快拖共存时，快拖时窗内的 9px 小位移不会提前补发。快拖到期仍静止则继续等待长按；同次按压命中其中一项后不再触发另一项。额外按键、滚轮、切窗、暂停、录制和替换绑定会取消相应等待或拖拽会话，必要的释放收尾继续处理。右键短按或快拖失败后的补发会改变原始输入时序与拖动起点，不能承诺无损恢复；系统调度也会影响浮窗实际显示时刻。参数与诊断见[触发预设、长按与快拖](TRIGGER_PRESETS.md)。

## 冲突规则

`MouseCapturedLeader` 只观察已有键盘引导会话，不参与前缀认领。注册要求存在同键的显式键盘层；缺少依赖时返回 `MissingCapturedLeader`，替换失败保留旧会话和滚轮余量。匹配要求引导键仍由当前层拥有，附加键和透传按压不能代替该身份。会话取消、快速输入回退、作用范围失效后，旧按压不能重新成为引导键；已经消费的鼠标末键仍拥有释放。额外键盘输入沿用原层策略，其他已认领的鼠标按压排除匹配。停用引导层而继续启用其鼠标引用会报错。

鼠标精确观察规则可显式设置 0–511 的匹配顺序，同应用优先级内数值越小越先。候选必须同时满足按住集合、前台及指针范围、位置条件，较高顺序不匹配时才继续查找。相同顺序的重叠规则仍冲突；顺序不能消除观察／捕获交付冲突，也不覆盖应用范围优先级。位置改变导致实际滚轮候选切换时，即使旧规则的位置条件仍成立，也会补发旧计数余量并重新计数，避免余量跨规则借用或丢弃。顺序不改变输入注入、重复、取消和释放的收尾规则。

鼠标观察规则显式设置 `pointer_scope_priority=false` 时，指针范围仅作为适用条件，不增加范围优先级；前台应用范围仍照常排序。省略此项保留指针白名单的原优先级。该选项不会把未知指针身份当成匹配，也不会改变其他键盘匹配模式。

`PointerRegion::ScreenBoundary` 使用显式屏幕矩形和事件坐标，固定匹配每块显示器的一像素边界，包含该屏幕的角点和与其他屏幕相接的边。它不读取系统状态，也不为相交边界设置优先级；相同输入且无法证明位置互斥时仍返回冲突。普通边缘和角落区域继续排除共享边段。移出边界或更新屏幕布局时，滚轮余量、待定前缀和已经消费的释放按现有条件失效规则收尾。

同优先级下，重复组合、普通按下与同组合的长按或快拖争用、同一组合配置多个长按或多个快拖会返回冲突；应用范围或位置条件可证明互斥时允许分别绑定。指定应用规则与全局回退可共存，优先级在按下时选定，普通按下不会抢先执行较低优先级的回退。同组合的一个长按与一个快拖可以共存，但同优先级下快拖时窗必须严格短于长按阈值。末键同时被其他组合用作前缀，且其动作所需的全部前缀也包含在另一组合的前缀中时，会抢先触发或预留末键，仍返回冲突；例如 `CapsLock+E` 与 `CapsLock+E+P`。只有应用或位置范围互斥才能消除这类冲突，不能仅靠优先级。界面禁止不限位置的裸左/右键“按下即触发”；可明确选择区域条件、长按或快拖。

## 尚不支持与系统限制

暂不支持双击、多击、顺序连击或按设备区分；Windows 安全桌面和系统保留组合仍受系统限制。

普通权限运行；向权限更高的应用补发输入可能失败，此时暂停监听并显示错误。无需安装驱动。其他软件在上游拦截输入时的表现见[并用其他工具与诊断](TROUBLESHOOTING.md)。

## 逐事件修饰快照

版本 23 的 `mouse_sampled` 由外层显式提供当前鼠标事件的修饰样本，核心只处理事件、样本、时间与已有按压归属。流标识、事件序号和取消代次必须一致；缺失、过期、未来或重复样本不会回退到旧值。Windows 在核心更新之外读取八个侧键，一份样本供全部候选共享，固定评估预算为16ms；这些读取不是原子操作，不能区分修饰状态是否来自其他软件注入。

策略分别指定修饰要求、额外修饰键、透传普通键和透传鼠标键的放行条件。被规则持有或等待收尾的按压会排除匹配；样本中存在修饰键不会为核心合成一次按下或建立捕获。动作仍经统一注册、范围与优先级选择。取消或替换绑定使旧代次失效，已经消费的鼠标末键仍按原归属收尾释放。旧入口每次都按无样本处理，不影响旧规则对输入事件的解释。
