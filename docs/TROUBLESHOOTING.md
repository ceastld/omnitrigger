# 并用其他工具与诊断

本页说明 OmniTrigger 与其他输入工具同时运行时的行为、“输入诊断”页的读法，以及常见问题的排查入口。

## 与其他输入工具并用

Windows 的同类低级 Hook 按后安装在前的顺序处理。其他软件若在上游拦截 CapsLock、侧键或滚轮，OmniTrigger 就可能收不到原输入；上游补发的模拟输入仍按原策略过滤，避免动作自触发。仅凭漏触发不能认定具体来源。

- “输入诊断”页每秒更新键盘/鼠标回调数、最近事件时间、外部模拟输入数、当前按住的键，以及自身补发、切换窗口取消和补发失败次数；底部状态栏显示简要计数。
- 长按诊断显示实际判定耗时、配置阈值、判定后的通知与显示提交耗时，并分别累计移动、切窗与短按 / 其他取消。可据此区分超时显示与候选被取消；数据只在内存保存，显示提交耗时不等于显示器像素亮起的时刻。
- 偶发失效时，松开其他按键后点击“重建监听”：旧监听先按原释放协议收尾，再启动新输入线程、重新安装 Hook，并恢复绑定及暂停状态；清除旧线程残留的按键状态。保留消息、录制结果和用户配置。
- 程序不定时重装 Hook 抢链首；其他软件稍后再次重装时，仍可能改变输入顺序。
- 输入线程结束或重建失败时明确显示未监听，不再维持“正在监听”的假状态。

可控优先级检查需要源码构建：`cargo run -p omnitrigger-windows --locked --example hook_priority_smoke`。测试 Hook 仅拦截专用标记的 F24 模拟探针，验证上游吞事件及重建后顺序变化；不改变其他应用，也不将探针交给前台窗口。

## 常见问题

| 现象 | 排查 |
| --- | --- |
| 启动提示缺少 `VCRUNTIME140.dll` | 安装 [Microsoft Visual C++ v14 Redistributable x64](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)。 |
| 组合偶尔不触发 | 查看“输入诊断”的回调计数是否增长；松开其他按键后点击“重建监听”，并检查是否有其他工具在上游拦截同一输入。 |
| 长按面板出现较慢 | 对照长按诊断中的判定耗时与显示提交耗时，区分候选被取消还是显示较慢，见[区分未触发与显示较慢](TRIGGER_PRESETS.md#区分未触发与显示较慢)。 |
| 监听暂停并提示补发失败 | 向权限更高的应用补发输入可能失败，此时暂停监听并显示错误。可以普通权限运行目标程序，或避免在该窗口中使用需要补发的前缀，然后在侧栏恢复监听。 |
| 亮度调节报错 | 亮度依赖显示器的 DDC/CI 或内屏 WMI 接口，不支持时明确报错，见[鼠标区域与系统调节](POINTER_REGIONS.md)。 |
| 截图插件无法安装 | 当前下载仓库需要访问权限；可改为填写本机已安装的 `raishot-cli.exe` 路径，见[快速开始](GETTING_STARTED.md#安装截图插件)。 |

报告问题时请使用仓库的 [Issues](https://github.com/ceastld/omnitrigger/issues)，说明 Windows 版本、复现步骤与诊断页计数。配置中的提示文字、诊断截图可能包含个人内容，提交前请自行脱敏；安全问题见[安全说明](../SECURITY.md)。
