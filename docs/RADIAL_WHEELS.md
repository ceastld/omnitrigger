# 自定义轮盘

轮盘将一组独立动作放在鼠标周围。可以为不同用途创建多个命名轮盘，再分别设置呼出组合；例如把复制、粘贴、全选和撤销放入“编辑轨道”。快速拖拽属于通用触发方式，轮盘属于动作：同一套快拖触发描述也可以绑定提示、发送快捷键或运行程序。

## 创建与管理

浮动轮盘使用透明窗口：圆形深色底盘承载动作扇区、中心提示和外圈刻度，在浅色或花哨的背景上也能看清；底盘以外的区域直接透出下方内容，不显示方形底板或系统矩形边框。

每个动作占据一块环形扇区，扇区的方向范围与选槽一致，绘制范围不超出可选中范围。选中时扇区以轮盘配色由内向外点亮、外沿发光，同方向的外圈刻度和中心指针一起亮起。不可用的动作带提醒图标，选中时扇区转为灰色，底部提示栏显示原因。显式多圈布局中，有动作的圈以暗色标出空方位，空方位不执行任何动作。中心未选中时显示轮盘名称，选中后显示编号、动作名和确认方式。

设置和“× 关闭”按钮并排停靠在轮盘上沿正中，分别有独立点击范围；关闭按钮使用红色悬停反馈，点击会取消当前选择，拖拽模式也可取消。

在主窗口侧栏进入“轨道轮盘”页面，创建或选择一个轮盘，设置名称和配色，再编辑槽位。页面中的“轨道预览”与浮动轮盘使用相同的扇区样式；点击扇区只选中对应槽位以便编辑，不执行动作；当前无法执行的槽位编号变暗，扇区边缘显示琥珀色提示。

- 最多保存 16 个轮盘。原有均分布局保留 1–8 个槽位；显式方位布局支持三圈稀疏排列，每组最多 48 个槽位。
- 轮盘名称和槽位名称支持中文，长度为 1–30 个字符。
- 配色提供薄荷、紫罗兰和琥珀三种选择。
- 槽位可以直接配置发送快捷键，也可以复制已有触发器中的普通动作，包括提示、运行程序、窗口操作、插件和外部动作。
- 可以调整槽位顺序、修改名称及删除槽位；保存时至少保留一个槽位。

槽位保存自己的动作参数。复制动作后，修改或删除原触发器不会改变该槽位；槽位不需要另行注册热键。槽位不能配置为打开触发面板或其他轮盘。

名称修改后点击“保存名称”，槽位编辑后点击“保存选中槽位”；颜色、顺序和增删操作分别保存。“打开预览”使用已保存的槽位，选择并确认后会真实执行动作。仍有呼出绑定引用的轮盘不能删除，需先修改或删除相应绑定。

首次没有轮盘配置时，程序提供“编辑轨道”，包含 `Ctrl+C`、`Ctrl+V`、`Ctrl+A` 和 `Ctrl+Z` 四个动作。默认轮盘不会自动注册呼出组合。

## 设置呼出组合

从轮盘管理页点击“设置呼出组合”，程序会从“右键快速拖拽”预设生成触发草稿，并将动作设为打开该轮盘：默认按下右键后，在 **180ms 之前** 相对按下点移动 **至少 18 个物理像素**。若已有同一轮盘的快速拖拽绑定，会直接进入该绑定的编辑界面，避免重复添加。

可以修改触发参数，也可以改为长按或普通按下、重新录制键盘和鼠标组合；确认后仍需保存触发器才会注册。原有的 `CapsLock + Tab` 等按下呼出绑定保持可用，不会自动改成快拖绑定。

呼出组合沿用现有 `TriggerSpec`、注册和冲突检查。组合已被占用或存在前缀冲突时，界面会指出冲突，不覆盖其他绑定。不同轮盘可以使用不同的呼出组合，同一轮盘也可以由多个绑定引用。

快速拖拽使用核心的 `Activation::Drag`。鼠标按钮、距离与时窗由触发器统一判断，轮盘窗口只负责展示与选择。一个右键快拖 `18px / <180ms` 可以与同组合的静止长按 `300ms` 共存：先认领快拖就取消本次长按，静止超过快拖时窗则继续等待长按。快拖时窗内移动 9px 不会立即触发长按回退。快拖时窗必须严格短于长按阈值；参数、取消与回退细节见[触发预设说明](TRIGGER_PRESETS.md)。

轮盘配置与触发器分别保存：保存轮盘内容不会自动注册组合，保存呼出绑定也不会执行槽位动作。

## 方位与应用覆盖

旧配置省略槽位的 `position`，仍按动作数量从正上方开始顺时针均分。显式布局为每个槽位指定圈号、分区编号和该圈的分区总数；未配置动作的方位保留为空，不会因删除槽位而重新均分其他动作。

`ring` 从内到外为 `0`、`1`、`2`，每圈的 `sectors` 为 `1`–`16`，`sector` 从 `0` 开始。默认 `sector: 0` 的中心在正上方，后续分区沿顺时针排列；`half_step: true` 将各分区中心沿顺时针偏移半个分区。同圈的分区总数和偏移必须一致，不能重复占用同一方位。同组槽位须全部指定方位，或全部省略方位。

`app_overrides` 可为最多 32 个应用分别保存完整槽位列表。`process` 使用进程文件名，例如 `editor.exe`，不包含目录，匹配不区分大小写；`@desktop` 专用于桌面背景窗口，与文件管理器窗口分开。命中应用覆盖时，其槽位列表整组替换全局槽位；无法读取前台上下文或没有匹配项时使用全局槽位。管理页当前编辑通用布局，应用专用布局保存在配置文件中。

每次打开轮盘时，程序按原前台窗口选择并冻结一份轮盘定义。显示与最终执行使用同一份槽位快照；切换前台会取消本次轮盘，下一次呼出再按新应用选择，避免显示一个应用的动作却执行另一组动作。

## 拖拽选择与松开执行

轮盘在鼠标附近显示，不移动鼠标，也不抢占原窗口的输入焦点。快速拖拽呼出后，继续按住原鼠标键并指向动作，**松开原鼠标键执行**。拖拽过程中左击、数字键或 `Enter` 不会提前执行槽位；`Esc` 可以取消。

选槽始终使用原物理按下点到当前物理位置的向量，从上方开始顺时针分槽。显式多圈布局还按半径选圈：物理位移除以打开时冻结的显示缩放，再判断圈号；同次拖拽不随窗口移位或后续缩放变化重新设定基准。

- 默认取消半径为 `min_distance_px / 2`，即 `18 / 2 = 9px`。回到原按下点 9px 半径内（含边界）再松开，会取消选择。
- 移出轮盘窗口或拖到较远位置，仍按这个固定向量的方向和半径选槽；最外圈向外延伸，不会因鼠标离开窗口而清除选择。落在空方位时没有动作。
- 靠近屏幕边缘时，窗口会调整显示位置以保留在工作区内；这个布局调整和显示缩放不会改变选槽起点。
- 若操作很快，在轮盘首帧出现前就已松开，仍按松开时的最终向量决定执行或取消，不要求先看见轮盘再释放。

拖拽的取消范围是原物理按下点附近的小半径，与普通点击模式中的可见中心安全区不同。窗口移位后不要用轮盘图形中心代替原按下点判断取消位置。

## 普通呼出的点击与键盘选择

通过原有 `CapsLock + Tab`、普通按下或长按绑定，以及“打开预览”和 `--wheel` 打开的轮盘，保留点击和键盘选择方式。先松开呼出组合，再选择动作；导航键在没有其他按键按住时接管，避免改写原有修饰组合。

- **鼠标**：移向一个方向选中对应槽位，单击左键确认。以窗口图形中心为基准，64 个逻辑像素半径的中心安全区、轨道圈外和窗口外不执行槽位；点击空白或外部位置会取消。
- **数字键**：按 `1`–`8` 执行槽位列表中前八项的对应可用动作；多圈布局也只提供这八个数字入口。
- **方向键**：在全部可用槽位中移动选择，再按 `Enter` 确认；不局限于前八项。
- **取消**：按 `Esc`、右键或点击轮盘外部收起轮盘。

| 交互 | 拖拽呼出 | 普通呼出 |
| --- | --- | --- |
| 选槽基准 | 固定物理按下起点，多圈半径使用冻结的显示缩放 | 轮盘窗口的图形中心 |
| 确认 | 松开原鼠标键 | 左击、数字键或方向键加 `Enter` |
| 取消区域 | 原按下点附近，默认 9 个物理像素半径 | 图形中心 64 个逻辑像素安全区及圈外 |
| 指针移出窗口 | 按物理向量继续选择，最外圈向外延伸 | 清除鼠标方向选择 |

## 执行与取消边界

核心为拖拽会话产生 `Started`、`Ended` 和 `Cancelled` 阶段，并携带会话标识（`session`）。展示层依照这些阶段显示、选槽或取消，旧会话的松开事件不会执行新一轮轮盘的动作。动作在原按压结束后交给外层执行，Hook 同步路径不运行槽位动作。

切换前台窗口、暂停监听、重建监听、开始录制或其他输入中断会取消拖拽；取消后不会因为原鼠标键随后松开而执行动作。已经消费的按下，其必要释放仍按输入收尾协议处理，不能把取消理解为对原输入的无损恢复。

执行前先收起轮盘，再将动作交给后台执行器。插件未就绪、程序配置有误或动作正在执行时，槽位会显示相应状态，不会绕过执行限制。快捷键动作仍会检查前台窗口及已按住的键；发送语义和限制见[发送按键与快捷键](KEYBOARD_ACTIONS.md)。

“窗口操作”是独立动作类型，当前提供最大化 / 恢复、最小化和关闭窗口（`close`，等同系统菜单“关闭”或 Alt+F4，应用仍可询问保存或拒绝）。后台线程对原目标调用 Windows 原生窗口 API，提交前核验窗口仍有效、可见、支持该操作且仍为前台。成功表示系统接受了异步请求，不代表目标应用已经完成处理。

“外部动作”显式保存依赖名称 `provider` 和 `command`，依赖程序必须使用绝对路径。依赖缺失时槽位标记为不可用；已知外部动作失效时，可通过可选的 `disabled_reason` 保存原因，阻止启动依赖程序。后台启动前再次核对轮盘打开时冻结的原前台目标，前台已变化就取消。命令交给外部进程后，OmniTrigger 无法强制约束该进程最终操作的窗口或目标；进程正常退出也不代表外部业务已完成。它与普通“运行程序”分别保存和显示，普通程序动作的参数规则见[外部命令说明](COMMAND_ACTIONS.md)。

尚未命中快拖就松开时，按触发器回退规则尽力交还原鼠标输入。超过快拖时窗时，同组合的长按若仍满足静止条件，就继续等待长按阈值；没有可继续等待的长按候选时才回退。补发会改变鼠标按下时序及原生拖动起点，不能保证完全无损，鼠标位移也不会重新注入。

## 启动时打开

构建应用后，可以直接进入轮盘管理页：

```powershell
.\target\debug\omnitrigger.exe --wheel-editor
```

启动完成后打开指定轮盘：

```powershell
.\target\debug\omnitrigger.exe --wheel orbit-edit
```

`--wheel` 只显示轮盘，等待选择，不自动执行任何槽位。单独使用该参数时主窗口不请求前台，保留原窗口的输入焦点；同时指定 `--wheel-editor` 则先进入管理界面。也可以使用独立配置目录试用：

```powershell
.\target\debug\omnitrigger.exe --config .\.local\wheel-demo\bindings.json --wheel-editor
.\target\debug\omnitrigger.exe --config .\.local\wheel-demo\bindings.json --wheel orbit-edit
.\target\debug\omnitrigger.exe --config .\.local\wheel-demo\bindings.json --check-config
```

`--check-config` 检查绑定格式、动作参数、组合冲突、轮盘配置和轮盘引用是否存在，不安装 Hook 或执行动作。

## 配置文件

轮盘内容保存在绑定文件同目录的 `wheels.json`，读取版本 1–3，保存版本 3。默认位置为 `%LOCALAPPDATA%\OmniTrigger\wheels.json`；使用 `--config` 时，轮盘文件也位于所选绑定文件的目录。版本 2 增加本地步骤动作，版本 3 增加通用 `invoke` 动作；首次保存旧版轮盘前保留 `wheels.json.v<旧版本>.bak` 备份。动作包使用同一调用结构，见[动作包说明](ACTION_PACKAGES.md)。

```json
{
  "version": 3,
  "wheels": [
    {
      "id": "orbit-edit",
      "name": "编辑轨道",
      "accent": "mint",
      "slots": [
        { "label": "复制", "action": { "kind": "send_shortcut", "keys": [162, 67] } },
        { "label": "粘贴", "action": { "kind": "send_shortcut", "keys": [162, 86] } },
        { "label": "全选", "action": { "kind": "send_shortcut", "keys": [162, 65] } },
        { "label": "撤销", "action": { "kind": "send_shortcut", "keys": [162, 90] } }
      ]
    }
  ]
}
```

`id` 是轮盘的稳定标识，使用 1–64 个 ASCII 字母、数字、连字符或下划线，同一文件中不能重复。`accent` 可取 `mint`、`violet`、`amber`，省略时使用 `mint`。旧均分布局的槽位顺序决定显示方位；显式布局的 `position` 决定显示方位。两种布局的数字键编号都沿用槽位列表顺序，只覆盖前八项。

`wheels` 数组中的三圈稀疏布局和应用覆盖示例：

```json
{
  "id": "work-tools",
  "name": "常用工具",
  "accent": "violet",
  "slots": [
    {
      "label": "复制",
      "position": { "ring": 0, "sector": 0, "sectors": 8 },
      "action": { "kind": "send_shortcut", "keys": [162, 67] }
    },
    {
      "label": "最大化 / 恢复",
      "position": { "ring": 1, "sector": 3, "sectors": 16, "half_step": true },
      "action": { "kind": "window", "operation": "toggle_maximize" }
    },
    {
      "label": "最小化",
      "position": { "ring": 2, "sector": 4, "sectors": 8 },
      "action": { "kind": "window", "operation": "minimize" }
    }
  ],
  "app_overrides": [
    {
      "process": "editor.exe",
      "slots": [
        {
          "label": "撤销",
          "position": { "ring": 0, "sector": 0, "sectors": 8 },
          "action": { "kind": "send_shortcut", "keys": [162, 90] }
        }
      ]
    }
  ]
}
```

上例在 `editor.exe` 中只使用“撤销”槽位，不再补入全局三个动作。外部动作的配置形态如下，路径和参数需替换为实际依赖程序：

```json
{
  "kind": "external",
  "provider": "示例工具",
  "command": {
    "program": "C:\\Tools\\Example\\runner.exe",
    "args": ["--action", "example"]
  }
}
```

呼出绑定保存在当前版本 8 的 `bindings.json`（读取兼容版本 1–8），动作字段只保存轮盘引用：

```json
"action": { "kind": "show_wheel", "wheel_id": "orbit-edit" }
```

右键快速拖拽呼出“编辑轨道”的一条绑定如下。`activation` 只描述触发条件，`action` 独立引用轮盘：

```json
{
  "id": 10,
  "held": [],
  "activation": {
    "kind": "drag",
    "value": {
      "button": { "kind": "right" },
      "min_distance_px": 18,
      "max_start_ms": 180
    }
  },
  "message": "打开编辑轨道",
  "enabled": true,
  "action": { "kind": "show_wheel", "wheel_id": "orbit-edit" }
}
```

将示例添加到 `bindings` 数组时，`id` 需使用当前配置中未占用的编号。

引用缺失时保留原绑定并标记不可用，修复或选择有效轮盘后再使用。轮盘文件损坏、包含未知字段或使用不支持的版本时会报错，保存操作不会覆盖该文件。正常保存先在同目录写完整临时文件，再替换原文件；保存失败时保留原文件。

关闭主窗口会退出应用，轮盘与全局监听一并结束。
