# 浮动触发面板

触发面板把已配置的动作放在一个可快速呼出的浮动窗口里。既可以直接按组合执行动作，也可以先用键盘或鼠标组合呼出面板，再点击动作。

## 打开与使用

主窗口侧栏提供“打开触发面板”。面板以当前鼠标位置为中心显示，鼠标位置保持不动。面板限制在鼠标所在显示器的工作区内；靠近屏幕边缘时会调整窗口位置，此时鼠标可能偏离面板中心。

应用启动时会预创建并隐藏面板，准备图形资源。收起时仅隐藏窗口，再次呼出复用同一个窗口；触发通知直接唤醒界面，不等待维护轮询。右键长按仍按配置的阈值判定，例如 `300ms`；系统调度和屏幕刷新仍会影响最后显示的时刻。

显示调用在当前界面更新结束后提交，避免同步窗口消息重入界面更新产生等待。面板是无焦点浮窗：窗口带 `WS_EX_NOACTIVATE`，以 `SWP_NOACTIVATE` 置顶显示，不请求前台，呼出前的窗口保持输入焦点；点击卡片也不会激活面板，运行动作时原窗口仍在前台。只有点击筛选框时，面板才暂时取消不激活样式，并用原生 `SetForegroundWindow` 请求前台，确认获得前台后再调用 `SetFocus`；该路径不使用模拟按键或 `AttachThreadInput`，系统拒绝时面板显示提示，仍可点击。默认长按 `300ms` 与移动容差 `8px` 保持不变。

Windows 长按计时优先使用一次性高精度 waitable timer，不可用时尝试普通 waitable timer，再回退到 SetTimer。输入诊断中的“计时方式”显示实际后端；后端选择不会改变保存的长按阈值。

## 面板布局

面板宽 552 逻辑像素，由三部分组成：

- **顶部**：筛选框、监听状态（监听中 / 已暂停）、“管理触发器”和“关闭”两个图标按钮。
- **动作卡片**：三列排列，沿用绑定顺序。每张卡片只显示类型图标、动作名称（最多两行）和右上角的数字键或状态，图标区分提示、程序、快捷键和插件动作。
- **底部说明栏**：未选中动作时显示呼出组合（最多两组）和按键提示；悬停或用键盘选中动作后，改为显示该动作的组合键帽、动作说明（例如“运行程序 · wt.exe”）和状态说明。

窗口高度随动作行数变化，超过四行后在卡片区内滚动。显示时按目标显示器的 DPI 一并调整窗口尺寸；筛选不改变尺寸，避免输入时窗口跳动。没有动作时显示空状态和“管理触发器”按钮。

配置为“仅提示”的动作点击后显示提示；配置为“运行程序”的动作点击后提交外部命令。程序调用方式见 [外部命令动作](COMMAND_ACTIONS.md)。

卡片状态：

- **可运行**：悬停时提亮，点击运行；前九项显示数字键 `1`–`9`。
- **执行中**：显示琥珀色“执行中”，不能再次点击。
- **已停用**：仍显示在原位置，调暗且不能点击。
- **未就绪**：已启用，但插件或程序当前不可用；悬停或选中后，说明栏显示原因。

## 键盘操作

面板不取得前台，键盘输入仍进入原窗口。面板可见时，输入采集只接管单独按下的导航键；这些键的按下、自动重复与对应释放都不交给原窗口：

- `↑` `↓` 按行移动选中项，`←` `→` 按列移动。
- `Enter` 运行键盘选中的动作。只有先用方向键选择后才接管回车；没有选择时，回车仍交给原窗口。鼠标悬停只高亮卡片并更新说明栏，不作为 `Enter` 的目标，避免误运行指针下的卡片。
- `1`–`9`（含小键盘）直接运行当前结果中对应位置的可运行动作。
- `Esc` 收起面板，原窗口不会收到这次 `Esc`。

同时按住其他键（包括 Ctrl、Alt、Shift、Win 和鼠标按键）时不接管，仍交给组合匹配和原窗口；其他按键不受影响。监听暂停或录制期间不接管导航键，暂停时可直接点击卡片，或点击筛选框后用键盘操作。

## 筛选

点击筛选框后，面板取得前台并接收文字输入，占位文字由“点击此处筛选动作”变为“输入以筛选动作…”。筛选按动作名称、动作说明和组合文字做不区分大小写的包含匹配，并自动选中第一个可运行结果。此时按键由面板自身处理：

- 方向键、`Enter` 和 `1`–`9` 的作用与上面相同；筛选框有文字时，`←` `→` 用于移动光标。筛选时没有选中项，`Enter` 运行第一个可运行结果。
- 数字不会写入筛选框。输入法组字时，按键先交给输入法，数字仍可用于选词。
- `Esc` 有筛选文字时先清除筛选，筛选为空时收起面板。
- 切换到其他窗口会收起面板。收起时把前台交还给呼出前的窗口。

每次呼出都会清空筛选、取消选中，并恢复不激活状态。

## 收起与管理

- 点击可用卡片或按键运行后，面板先隐藏并收起，再由主窗口处理运行请求。
- 按 `Esc`、点击“关闭”或点击面板以外的位置，面板会收起。
- 点击“管理触发器”会收起面板，并打开主窗口的触发器页。
- 监听暂停时，仍可从侧栏打开面板并手动点击已启用动作；暂停会阻止键盘、鼠标组合触发，不等于停止手动执行。
- 录制期间不能打开面板。先完成或取消录制，再使用面板。

面板未取得前台时，靠输入采集收到的物理窗外点击收起。监听暂停等未接管 `Esc` 的情况下，物理 `Esc` 通知仍会收起面板，原窗口也会收到这次 `Esc`。面板为筛选取得前台后，`Esc` 由面板自身处理，失焦即收起。窗外右键按下会先收起面板；面板不改变前台窗口，正在等待的右键长按不会因此取消，达到阈值后在新位置重新显示。

## 执行与输入补发

面板不提供独立执行器：卡片和组合使用同一份绑定，运行仍受现有外部命令的并发及忙碌限制。成功启动外部程序只表示进程已创建，不表示其业务已经完成。

输入补发由独立后台线程完成，Hook 不再同步等待 `SendInput`。最多 512 项的有界交付队列按顺序处理离散按下 / 释放 / 滚轮及动作通知，只有一个输入批次在途。物理鼠标移动直接透传，不排队，也不注入位移；面板重定位仍只移动窗口。

面板动作通知排在更早的输入交付之后，长按保留原始匹配时刻。旧批次回执按各轮按压的独立编号结算；队满或补发失败时暂停监听，并保留已交付按下所需的释放收尾。退出会检查待发、在途和清理状态；原生 `SendInput` 无法取消，最后释放仅尽力完成，不能承诺无损恢复。旧补发线程未结束时，重建监听会明确提示暂不可重建。

## 配置面板呼出组合

没有已有配置的首次运行，示例会包含 `CapsLock + Space` 和右键长按 `300ms`。`CapsLock + Space` 切换面板的显示状态；右键长按每次在当前鼠标位置显示面板，已打开时也会移动到新位置。侧栏“打开触发面板”保留显示 / 收起切换。长按的短按回退、移动取消和时序限制见[预设与长按说明](TRIGGER_PRESETS.md)。

已有配置加载后，不会自动增加呼出组合，以保留原有绑定。可在“触发预设”中选择“右键长按 300ms”，再将动作选择为“触发面板”，确认后添加；也可以按以下步骤录制自己的组合：

1. 恢复监听，在侧栏点击“录制面板呼出组合”。
2. 按住前缀，再按目标键或滚动滚轮，全部松开完成录制；`Esc` 取消。
3. 检查录制结果。动作类型会自动选择“触发面板”，并填入提示文字。
4. 点击“添加触发器”保存。之后可在其他窗口使用该组合呼出面板。

也可以通过普通“录制组合”创建绑定，再把动作类型改为“触发面板”后保存。键盘和鼠标组合沿用现有录制能力与限制。

呼出组合和普通动作共用 `TriggerSpec`、注册规则与冲突检查。组合重复、终端键与前缀冲突等情况会明确报告，不会自动改写或覆盖已有绑定。修改已有绑定的动作类型时，仍需点击保存。

“触发面板”动作用于打开或收起面板，是一种控制动作，不会作为卡片出现在面板中，避免点击面板里的卡片又打开同一个面板。一个绑定不能同时配置为外部程序动作和面板控制动作。

## 长按与显示耗时诊断

“输入诊断”显示最近长按判定的经过时间、配置阈值与成功匹配时的超出量，并提供本次运行观测到的最大判定迟到量。“上次长按至面板提交”显示最近一次总耗时与本次运行最长耗时；“判定后的界面耗时”拆分为通知与显示两个阶段。

“最近 8 次长按结果”按最新在前排列，只包含已经开始计时的操作，每项显示结果、经过时间和阈值。它区分命中、短按松开、移动、切窗、其他按键、滚轮、配置、暂停、录制及恢复等结果。已注册长按目标的按下 / 释放、开始 / 未开始、重复鼠标按下另行计数，并概括最近一次未开始的原因。

“面板显示与收起”统计界面呼出请求、原生提交、跳过和失败，以及面板呈现、收起和失焦收起，并显示最近的显示阶段及面板事件。这些摘要可帮助区分尚未开始匹配、计时后取消和后续显示过程。

“Hook 墙钟耗时最大值”分别列出本项目 Hook 本体、下游 `CallNextHookEx` 链和后台 `SendInput` 补发的最大耗时及慢调用次数。每段严格超过 `50ms` 才计为慢调用，后台补发由独立线程执行，已不包含在 Hook 本体中。墙钟时间包括线程被系统抢占的等待，并非 CPU 执行时间；蜂鸣或鼠标短暂停顿需要结合这些分段数据排查，不能据此认定唯一根因或卡顿已经完全解决。

这些统计及最多八项长按结果摘要只保留在本次运行的内存中，不记录任意原始按键或鼠标坐标历史。面板提交总耗时计至原生显示及激活请求返回，不能代表屏幕像素亮起的时刻。取消操作不会更新上次成功显示的总耗时。不能仅凭这些数据确认某次体感延迟或未触发的根因，也不保证精确 300ms 呈现或零漏触发。字段含义与阅读方法见[预设与长按说明](TRIGGER_PRESETS.md#区分未触发与显示较慢)。

## 计数与记录

面板点击和组合命中分别统计。点击卡片会增加本次运行的面板点击计数，并在“触发记录”中标记为“面板”；不会增加该绑定的组合命中次数或更新组合最近命中时间。触发记录可以单独筛选“面板”。

使用呼出组合显示、重新定位或收起面板属于真实组合命中，按普通输入来源记录。预览提示仍使用“测试”来源，三种来源保持区分。统计与触发记录只保留在本次运行期间。

## 启动时显示与隔离试用

构建后，可以让程序在启动完成后直接打开面板：

```powershell
.\target\debug\omnitrigger.exe --panel
```

使用独立配置文件试用，不修改日常使用的绑定：

```powershell
.\target\debug\omnitrigger.exe --config .local\panel-test\bindings.json --panel
```

`--config` 后面的参数是本次进程使用的配置文件路径。文件尚不存在时加载首次运行示例，之后的保存写入该路径。

绑定配置当前保存为版本 7，读取兼容版本 1–7；面板呼出使用统一动作字段 `"action": { "kind": "show_panel" }`。首次保存旧配置前保留带旧版本号的备份。[右键长按示例](../examples/right-hold-panel.json) 使用当前格式，可复制到独立目录试用。

## 当前限制

关闭主窗口会退出应用，触发面板和输入监听也随之结束。当前没有系统托盘常驻或拖动排序；面板卡片沿用绑定顺序，动作及组合在主窗口管理。筛选只做文字包含匹配，不支持拼音或模糊匹配。

面板是 OmniTrigger 的本地动作入口，展示已配置绑定，并与组合触发共用应用层执行入口。插件依赖由动作库管理，执行能力与限制见 [动作执行架构](EXECUTION_ARCHITECTURE.md)。
