# 配置档与数据目录设计

状态：设计目标，尚未实现。当前程序把所有数据放在 `%LOCALAPPDATA%\OmniTrigger` 的一组 JSON 文件中，`--config` 可以临时指定另一个路径；没有配置档、切换界面、自动备份或单实例保护。

本页解决三个问题：

- 用户的真实数据、测试数据和演示数据混在同一位置，测试或截图容易改到用户数据。
- 程序没有单实例保护，多个实例同时安装 Hook，同一组合可能触发两次，各实例还可能互相覆盖配置。
- 从打包应用（例如某些桌面 Agent 客户端）启动时，Windows 会把 `%LOCALAPPDATA%` 写入重定向到该应用的私有目录，同一台机器上出现两份互不知情的数据。

账号、云同步和存储引擎的设计见[账号工作区与同步设计](ACCOUNT_WORKSPACE.md)，本页定义它们在本机落地所依赖的配置档层。

## 概念

| 概念 | 含义 |
| --- | --- |
| 数据根 | 本机唯一的 OmniTrigger 数据目录，所有配置档和本机数据都在其下。 |
| 配置档 | 一份完整、相互隔离的用户数据：动作、绑定、轮盘、动作包和个人偏好。同一时刻只有一个配置档处于活动状态。 |
| 配置档类型 | 本地、账号、测试三种，见下表。 |
| 本机数据 | 与配置档无关、只属于这台机器的数据：插件运行时、程序路径映射、设备映射、窗口位置。 |

| 类型 | 用途 | 同步 | 外观标识 |
| --- | --- | --- | --- |
| 本地 | 默认类型，即“离线账号”。未登录也能完整使用，之后可以关联账号。 | 不同步 | 无 |
| 账号 | 已关联 OmniTrigger 账号的配置档，离线时照常使用，联网后后台同步。 | 同步 | 显示账号名 |
| 测试 | 演示、截图、开发验证；可从示例或当前配置档复制创建，随时丢弃。 | 永不同步 | 醒目的“测试数据”标记 |

离线账号不单独建模：本地配置档就是离线账号，关联账号后转为账号配置档，ID 和数据不变。这样“先离线用，再登录同步”不需要迁移或合并。

## 目录结构

```text
%LOCALAPPDATA%\OmniTrigger\
  profiles.json                  配置档目录：列表、活动配置档 ID、类型、显示名
  profiles\<配置档 ID>\
    workspace\                   用户数据（当前 JSON，之后为 SQLite 与内容仓库）
    packages\<包 ID>\            托管动作包：不可变修订与可编辑的工作副本
    backups\                     该配置档的自动备份
    sync\                        账号配置档的同步元数据（仅账号类型）
  device\                        本机数据：程序路径映射、设备映射、窗口状态
  plugins\                       插件运行时缓存，各配置档共享
```

- 配置档 ID 是创建时生成的随机稳定 ID，不使用显示名或账号邮箱作目录名。改名不移动目录。
- 首次升级时，把现有 `bindings.json`、`wheels.json`、`appearance.json`、`plugins.json` 和 `actions\` 迁入一个名为“我的配置”的本地配置档，迁移前保留原文件副本；`actions\` 中的包导入为托管包。
- 链接目录动作包的路径属于本机数据，存于 `device\`，不进入配置档。动作内容的三种来源见[动作包说明](ACTION_PACKAGES.md)的“动作内容来源与托管”一节。
- `--config <路径>` 保留为开发入口，表示“临时配置档”：数据直接读写指定路径，不进入 `profiles.json`，不同步，界面显示测试标记。

## 单实例与切换

每个 Windows 用户会话只允许一个 OmniTrigger 实例安装 Hook：

- 启动时获取会话内的命名互斥量。已有实例时，把命令行参数（打开窗口、`--profile`、规划中的 `--run <动作 ID>`）转交给它，然后退出。
- 开发需要并行运行时，用 `--config` 启动的临时配置档使用独立互斥量，且默认不安装 Hook，只有显式加参数时才监听。

切换配置档在运行中的实例内完成，不需要重启：

1. 取消正在进行的前缀暂存、长按、面板和轮盘；已消费的按下补齐释放，与暂停监听的收尾规则相同。
2. 停止旧配置档的同步任务，撤下触发快照。正在执行的动作继续完成，回执带配置档代次，不写入新配置档。
3. 加载新配置档，通过冲突检查后整体替换触发快照；失败时保留旧快照并显示结构化错误。
4. 记录新的活动配置档，下次启动沿用。

输入核心只接收新的快照，不感知配置档。

## 打包应用的重定向

从打包应用启动的进程，写入 `%LOCALAPPDATA%` 时会被重定向到 `%LOCALAPPDATA%\Packages\<包名>\LocalCache\Local\...`，读写的是另一份数据。处理方式：

- 启动时检测当前进程是否运行在打包应用上下文中。
- 如果是，不在该上下文中加载数据，而是通过系统外壳重新启动自身，脱离打包上下文后再走单实例流程。重新启动失败时，显示数据会被重定向的说明，不静默使用重定向目录。
- 发现某个打包应用的私有目录中已有 OmniTrigger 数据时，提示用户导入为一个配置档，不自动合并。

## 备份与恢复

- 每次保存前，把将被覆盖的文件放入该配置档的 `backups\`。保留最近 20 次，另外每天保留一份，最多 30 天。
- 迁移、切换前的冲突处理、同步合并和导入前，额外创建一份带原因标记的快照。
- 设置中可按时间查看备份、恢复为当前数据，或另存为新配置档。恢复本身也先备份当前数据。

## 与账号的关系

| 操作 | 行为 |
| --- | --- |
| 本地配置档关联账号 | 云端为空时上传；云端已有数据时由用户选择：使用云端、上传本地或另存为新配置档。不自动合并、不覆盖。 |
| 新设备登录 | 新建账号配置档并下载数据；本机已有的本地配置档保持不变。 |
| 退出登录 | 停止同步、清除会话凭据，配置档转为本地类型继续可用，并标记“已退出，未同步”。 |
| 删除 | 删除本机配置档、删除云端数据和退出登录是三个独立操作，均需确认。 |

- 每个配置档最多关联一个账号；同一账号在本机只对应一个配置档，避免两份本机副本与同一云端工作区冲突。
- 测试配置档不能关联账号；需要同步时先复制为本地配置档。
- 本机数据（`device\`、`plugins\`）不随配置档或账号同步，同步范围见[账号工作区与同步设计](ACCOUNT_WORKSPACE.md)。

## 界面

- 侧栏底部显示当前配置档名称。测试和临时配置档使用醒目色块，一眼可见当前不是自己的数据。
- “设置 → 配置档”是唯一管理入口：切换、新建（空白 / 从示例 / 复制当前）、改名、导入导出、备份恢复和关联账号。
- 切换是一个主操作：选中即切换，不要求重启或确认路径。

## 实现顺序

1. 单实例互斥量与参数转交，`--config` 临时配置档使用独立互斥量。
2. 打包上下文检测与重新启动。
3. 保存前自动备份与恢复入口，先在现有单文件配置上生效。
4. 数据根、`profiles.json` 与旧配置迁移；运行中切换配置档。
5. 测试配置档、侧栏标记与设置页管理界面。
6. 账号关联与同步，按[账号工作区与同步设计](ACCOUNT_WORKSPACE.md)的实现顺序推进。
