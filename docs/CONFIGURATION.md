# 配置文件与隐私

OmniTrigger 的绑定、插件与轮盘配置都保存在本机 JSON 文件中。本页说明文件位置、版本迁移、外部程序的运行方式及隐私边界；各动作的字段见对应专题文档。

## 配置文件位置

绑定、提示文字、位置条件与动作参数保存在 `%LOCALAPPDATA%\OmniTrigger\bindings.json`；没有 `LOCALAPPDATA` 时使用系统临时目录下的 `OmniTrigger\bindings.json`。初次运行加载示例，之后保留用户配置，编辑后自动保存。

启动时加 `--config <文件路径>` 可以使用独立配置，后续编辑保存到该文件；`--check-config` 只读检查所选配置，不安装 Hook 或执行动作。完整参数见[快速开始](GETTING_STARTED.md#命令行参数)。

| 文件 | 位置 | 内容 |
| --- | --- | --- |
| `bindings.json` | 默认目录或 `--config` 指定 | 绑定、触发描述、位置条件、提示与动作参数 |
| `plugins.json` | 与绑定文件同级 | 插件启停和共享程序路径 |
| `plugins\raishot\manifest.json` | 与绑定文件同级 | 可选的开发者 RaiShot 动作清单；缺失时使用内置清单 |
| `wheels.json` | 与绑定文件同级 | 轮盘名称、配色、槽位与应用覆盖 |
| `plugins\raishot\runtime\0.4.15` | 与绑定文件同级 | 早期版本下载的截图插件运行文件，仍可被复用；新下载位于 `%LOCALAPPDATA%\Programs\RaiShot` |
| `actions\<包目录>\action.json` | 与绑定文件同级的 `actions` | 本地动作包清单及其引用的 JS 入口；启动时加载 |

## 版本与备份

浏览器连接器的本机状态独立保存在配置同级 `browser-connector.json`，版本程序位于 `plugins/browser-connector/runtime/0.1.0`。用户点击安装后，本机注册与启动自动完成，这些内部文件无需手工编辑。实现细节见[浏览器连接器](BROWSER_EXTENSION.md)。

`bindings.json` 读取兼容版本 1–13，保存使用版本 13；首次保存旧配置前创建 `bindings.json.v<旧版本>.bak` 备份，备份失败不会覆盖原配置。版本 8 增加 `invoke` 动作引用，版本 9 增加 `browser` 浏览器动作，版本 10 增加 `process_scope`，版本 11 增加 `keyboard` 专用层与重复策略，版本 12 增加显式捕获集合匹配，版本 13 增加快捷键按下时序。回退旧程序时需恢复对应备份。

版本 13 的 `send_shortcut` 动作可添加 `"timing": {"key_down_delay_ms": 5, "process_overrides": {"wps": 10}}`。省略时延迟为零；覆盖值按原目标进程文件名匹配，忽略大小写及可选的 `.exe`，最多 16 项，不接受路径、通配符或重复别名。每个延迟是 0–1000ms 整数；设置了进程覆盖但无法读取目标身份时拒绝执行。界面修改快捷键会保留原时序，详细发送顺序见[按键动作](KEYBOARD_ACTIONS.md)。

## 触发器的应用范围

版本 10 的单条绑定可配置 `"process_scope": {"allow": ["Code", "cursor.exe"], "deny": ["game.exe"]}`。省略该字段表示全局；`allow` 为空表示所有已知应用，`deny` 再作排除。按映像文件名匹配，忽略大小写，可省略 `.exe`；不支持路径、通配符或分号分隔，一个名称对应一个数组项。两个列表合计最多 64 项；重复名称、非法名称或白名单全部被排除时明确报错。

同组合的指定应用规则优先于全局规则，是否指定应用以非空 `allow` 为准；同优先级的范围重叠仍报冲突。排除列表本身不提高优先级。进程身份未知时，有范围的规则不命中，与指定应用规则共用组合的全局回退也暂不执行；无关的全局组合继续有效。应用范围和鼠标位置条件共同生效，前台窗口或进程改变时取消旧按压，旧释放继续正确收尾。

当前通过配置文件设置应用范围；触发器列表与详情显示该限制，编辑动作、切换触发方式和重新录制组合均保留它。范围仅限制输入触发，不限制用户在动作库或面板中主动运行该动作。Windows 在 Hook 回调之外查询前台进程，并按前台通知更新；无法读取时保留未知状态。诊断 API 的 `foreground_process` 仅保存当前名称，不记录历史。

插件启停和共享程序路径保存在绑定文件同级的 `plugins.json`，通过“启用 RaiShot”自动识别或下载安装后保存。使用 `--config` 时，插件设置、可选动作清单和下载目录也位于所选配置文件的目录，便于隔离试用；复用的已有安装仍保留在原位置。`plugins\raishot\manifest.json` 在启动或刷新时读取，清单损坏或版本不兼容会明确报错并保留原绑定，不回退到内置动作掩盖错误。清单格式与手动路径排障见[插件说明](PLUGIN_SYSTEM.md#开发排障入口)。旧程序动作保持原始参数，不自动转换成插件引用。

轮盘内容保存在绑定文件同级的 `wheels.json`，读取版本 1–5，保存版本 5，版本 3 支持 `invoke` 动作、版本 4 支持 `browser` 动作、版本 5 支持快捷键时序；保存旧版前保留逐字备份。可选的 `position` 保存圈号、分区和半分区偏移，`app_overrides` 保存按进程文件名匹配的完整槽位替换。呼出组合在绑定文件中保存 `show_wheel` 动作与轮盘标识。每个槽位独立保存动作参数，不随复制来源的绑定更改。轮盘引用缺失时保留绑定并标记不可用；损坏或不支持的轮盘配置不会被保存操作覆盖，保存失败时保留原文件。配置形态见[自定义轮盘](RADIAL_WHEELS.md)。

动作包引用保存 `package_id`、`action_id`、`action_version` 与 JSON 对象 `input`。保存配置只验证调用结构；运行时解析包与动作版本。包缺失或不兼容时保留原引用及参数，将对应绑定标记不可用，不静默改为其他动作。包清单的 `schema_version`、包发布 `version`、动作契约 `version` 与绑定文件版本独立，详见[动作包说明](ACTION_PACKAGES.md)。

## 专用键盘层与按住重复

版本 11 的单条绑定可添加：

```json
"keyboard": {
  "dedicated_prefix": {"kind": "key", "value": 20},
  "repeat": true,
  "restore_on_tap": true,
  "tap_timeout_ms": 20000,
  "tap_scope": {"allow": ["notepad.exe"]}
}
```

省略 `keyboard` 保留普通前缀回退及单次触发。`dedicated_prefix` 必须是本条 `held` 中的明确键盘键；鼠标键、泛型 Shift/Ctrl/Alt VK、未在组合中的键均报错。重叠应用和位置范围内，同一前缀的层模式、单按恢复、恢复范围及超时须一致，不会暗中修改其他组合。`repeat` 可独立启用，只支持键盘 `press`，其他触发方式明确拒绝。

专用前缀按下时进入层，单独松开不回放；层内未绑定键盘输入和修饰层前缀也被消费，释放成对收尾。鼠标点击和未绑定滚轮继续按原规则透传；已认领的鼠标前缀失败时仍交还，滚轮余量单独补发。若前缀按下前已有交付给应用的输入，则只抑制专用键自身，不借用旧按压进入层。层只在有适用绑定的应用和位置范围内生效。

如需保留 CapsLock 等专用键的独立用途，可启用 `restore_on_tap`：没有其他键盘输入、没有命中动作或绑定滚轮时，松开后补发该键的一次点击。未绑定鼠标输入本身不取消这次单按。`tap_timeout_ms` 可限定等待时间，需严格小于此值才恢复；省略则不限时。超时仅在开启单按恢复时有效，范围为 1–60000ms；注入事件不取消单按。补发仍受前台、权限和失败恢复约束，不能当成无损恢复。

`tap_scope` 使用与 `process_scope` 相同的白黑名单格式，只限定单按恢复，不改变整个专用层的范围。上例中其他组合在层内继续有效，只有记事本中的独立单按会恢复原键。省略则恢复范围为全局；指定范围而进程未知时不恢复。关闭 `restore_on_tap` 时不能保留非空的 `tap_scope`。

提前释放专用前缀时，其他已消费键继续等待各自释放，不能借给新组合。暂停、切窗、换绑或移出层的范围会结束该层；仍被按住的旧键不重新触发。层内键盘长按的短按与取消不回放为普通键。重复只执行本次按压最初命中的动作，额外按键会阻止不再匹配的重复；作用范围失效后，必须松开重按才能再次触发。注入事件仍忽略，不触发重复。

目前在配置文件中设置这些策略，列表与详情显示它们；编辑或重新录制保留策略。更换专用键或把重复绑定改为长按时，应先明确修改策略，校验不会悄悄删除原设置。示例见 [`dedicated-keyboard-layer.json`](../examples/dedicated-keyboard-layer.json)。

### 捕获集合匹配

版本 12 可在 `keyboard` 中添加 `"matching": {"kind": "captured", "priority": 0}`。缺省或 `{"kind":"exact"}` 仍精确匹配物理按下集合。捕获模式要求专用键盘层、键盘 `press`，每条至多一个附加键（`held` 中除引导键外的键）。完整例子见 [`captured-keyboard-layer.json`](../examples/captured-keyboard-layer.json)，初始均停用。

捕获层先按已有捕获集合选择动作；没有命中时，只有当前适用规则所声明的附加键才会被捕获。未识别键和首次按下就命中动作的末键会被抑制，但不进入捕获集合，也不阻止无附加键的默认规则。多个附加键可同时保留，各自释放时移除；捕获来源的位置条件失效后，旧按压不能重新成为前缀。

指定应用规则先于全局规则；同一应用优先级内，`priority` 越小越先选，取值 0–511。相同末键、重叠范围中的同级规则不能使用相同顺序编号。捕获模式允许动作末键同时被声明为另一规则的附加键：动作先执行，这次按压不会因此自动捕获。一个层不能混用精确与捕获模式；暂停、切窗、换绑或释放引导键都会结束捕获。

捕获模式的 `repeat` 按当前捕获集合重新选择动作，可以随附加键的释放切换到默认规则；已捕获的键因重复触发动作后仍保留捕获角色。它不同于精确模式的原动作重复。若层中有指定应用规则而进程未知，整个捕获层暂不启用。删去或停用高优先规则可能改变默认回退，迁移时必须核验完整规则集，不能只启用其中几个动作就认领整个专用层。

## 外部程序与脚本

普通“运行程序”的程序与参数逐项传递，不默认经过 Shell，不展开环境变量或引号，也不自动重试。外部程序按当前用户权限运行；仅启动自己信任的程序和脚本。进程正常退出不代表插件业务已完成，这条执行路径不采集标准输出与错误输出。暂停监听只阻止新触发，退出 OmniTrigger 不会终止普通命令已启动的外部程序。见[程序与脚本](COMMAND_ACTIONS.md)。

JS 动作包使用独立 Node 宿主和结构化结果协议，`ctx.process.run` 有界采集进程输出。脚本按当前用户权限执行，独立宿主不是安全沙盒；脚本及其启动的程序可能访问文件或网络。取消不回滚副作用，具体收尾边界见[动作包说明](ACTION_PACKAGES.md#执行与权限边界)。

## 隐私

当前应用不提供遥测、云同步或输入上传。插件安装会访问 GitHub 下载程序及运行依赖，不上传输入事件或截图；全局监听用于本机匹配与录制，触发记录和输入诊断仅保留在进程内。配置中的提示文字、诊断截图可能包含个人内容，报告问题前请自行脱敏。

可试用的配置示例位于仓库的 [`examples/`](../examples/)，均可通过 `--check-config` 验证。
