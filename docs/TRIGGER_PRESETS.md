# 触发预设、鼠标区域、长按与快速拖拽

常用触发器不需要编写脚本。操作顺序是：**选择预设 → 调整参数 → 选择动作 → 保存**。预设提供一个可编辑的触发器描述，保存前仍按同一套注册规则检查冲突，不覆盖已有组合。

## 从预设开始

在主窗口左侧打开“触发预设”，点击预设卡片即可选用。目前有 23 项，按五组展示：

| 分组 | 预设 |
| --- | --- |
| 快速拖拽 | 右键快速拖拽：18px / 180ms |
| 屏幕区域 | 四条边缘 + 滚轮；四个角落 + 滚轮 |
| 长按 | 右键长按 300 / 500 / 800ms；中键长按 300ms；侧键 1 / 2 长按 300ms；F8 长按 500ms |
| 键盘组合 | `CapsLock + Space`；`左 Ctrl + 左 Alt + Space` |
| 单键与鼠标组合 | 单按 F8；单按鼠标侧键 2；侧键 1 + 滚轮上滚 / 下滚；左 Shift + 右键 |

选择后会进入触发器页，只更新触发方式，保留当前动作与参数。例如先选择截图动作，再选择右键长按或快速拖拽，动作仍是截图。可以调整触发参数和名称，最后点击“添加触发器”。需要呼出面板时，请明确选择“触发面板”动作，或使用侧栏“录制面板呼出组合”。需要打开轮盘时，选择相应轮盘动作；快速拖拽预设本身不指定动作。长按时长支持 **50–10000ms**；无效数值会明确拒绝，不会自动改成另一个时长。

选择预设不会立即注册或执行动作。与已有触发器重复、普通按下与同组合的长按或快速拖拽争用、同一组合配置多个长按或多个快速拖拽、目标键与其他组合的前缀冲突时，界面会报告冲突；位置条件可证明互斥时可以分别绑定，相交时不暗设优先级。一个长按与一个快速拖拽可以共存，快拖时窗必须严格短于长按阈值。可以修改草稿或编辑已有绑定。

也可以先录制普通按键组合，全部松开后，在“触发方式”中选择“长按”，填写“长按时间（毫秒）”，再选择动作并保存。“按下即触发”可改回普通按下。长按适用于一个目标键或鼠标按钮；滚轮方向没有按住时长，仍使用滚轮触发。单独录下不限位置的左键或右键时，普通按下会先提示不能使用；可选择位置条件、长按或快拖后重新检查。

没有已有配置的首次运行，默认包含 `CapsLock + Space` 和右键长按 300ms 两个面板呼出入口。`CapsLock + Space` 切换显示 / 收起；右键长按用作面板动作时，每次都在当前鼠标位置显示面板，已打开时重新定位。再次选择相同预设会报告重复，可以在“触发器”列表中编辑已有条目并点击“保存动作”。已有配置加载后保持原有绑定，不自动增加右键组合；可从左侧“触发预设”添加需要的入口。

## 鼠标位置条件与系统调节

“屏幕区域”八项模板分别提供四条边和四个角落，默认滚轮上滚；边缘厚度为 8 个物理像素，角落边长为 32 个物理像素。位置保存在 `TriggerSpec.conditions`，触发方式保存在 `activation`，动作独立保存。可以改为下滚、左滚、右滚，或重新录制按键、鼠标按钮，再选择长按或快拖；重新录制会保留当前已选条件。

在触发器详情中也可选择“不限位置”或输入自定义半开矩形。边缘厚度支持 1–256px，角落边长支持 1–1024px；参数是最大范围，受对应半屏归属限制。屏幕区域使用完整显示器范围，部分相接的边只排除共享段，连接角也不作为外露角落。

动作类型“系统调节”提供原生音量、硬件背光的增加和减少，单次幅度为 1–100 个百分点。分别保存滚轮上、下两条绑定即可双向控制；模板本身不指定音量或亮度，也不会自动启用。完整配置、跨屏规则、设备支持与恢复边界见[鼠标区域条件与系统调节](POINTER_REGIONS.md)。四条可独立试用的绑定见[边缘调节示例](../examples/screen-edge-adjustments.json)。

## 插件默认快捷键

插件动作也可声明默认触发方式。当前 RaiShot 截图适配提供 `左 Ctrl + 左 Alt + A`：在动作库点击“设置触发”填入草稿，安装插件本身不注册该组合。用户可录制自定义快捷键、选择本页预设，或点击“恢复默认”。恢复只修改所选动作的触发草稿，保存前仍检查已有绑定和前缀冲突，不覆盖其他组合。

## 右键长按 300ms 的行为

按下右键后，OmniTrigger 暂存这次按下，等待确认是普通右键还是长按：

- **不足 300ms 松开**：不触发动作，补发一对右键按下与释放，让前台应用处理普通右键操作。
- **达到或超过 300ms**：本次按压只触发一次。恰好在 300ms 松开也按长按处理，最终的物理释放会被消费，不再弹出普通右键菜单。
- **只有长按候选时，鼠标离开按下点超过 8 个物理像素**：取消长按并回退。8 像素是相对按下点的容差半径，不按累计移动路程计算。若同时注册快速拖拽，快拖时窗内会继续等待，避免 9px 小位移提前补发，具体见下节。
- **尚未到时，出现其他按键或滚轮输入**：取消长按并按回退规则交还输入，不继续等待弹出面板。
- **前台窗口切换、暂停监听或替换绑定列表**：丢弃尚未交付的缓冲，并消费必要的后续释放，避免将旧输入补发到新窗口。
- **自身补发及其他软件注入的输入**：不参与长按匹配和录制，避免补发再次触发。

300ms 是匹配阈值。Windows 优先使用一次性高精度 waitable timer；不可用时尝试普通 waitable timer，再回退到 SetTimer。实际使用的“计时方式”可在“输入诊断”查看。系统计时与界面调度仍会影响面板实际出现的时刻，不能保证从按下到面板显示恰好为 300ms。

右键原始输入会被延后，回退也不等于无损恢复。特别是右键拖动：超过移动容差后才补发按下，前台应用看到的拖动起点可能偏移，开始阶段的运动和时序也会改变。依赖精确右键拖动的软件可以改用侧键、键盘组合或更适合的预设。

## 右键快速拖拽与长按并用

“右键快速拖拽”是通用鼠标触发方式。默认需要按下右键后，在 **180ms 之前** 相对按下点移动 **至少 18 个物理像素**；距离使用直线半径，不按累计路程计算。命中时认领这次拖拽，只执行快拖动作一次，取消同次按压的长按候选，并消费最终释放。

同一组合可分别配置 `快速拖拽 18px / 180ms` 与 `长按 300ms`，各自选择动作。两者共用输入状态：

| 操作 | 结果 |
| --- | --- |
| 在 180ms 之前达到 18px | 执行快速拖拽动作，不再执行长按动作。 |
| 快拖时窗内只移动 9px，尚未达到 18px | 继续等待快拖判定，不因超过长按的 8px 容差而立即补发。 |
| 到 180ms 仍在 8px 容差内，继续按住 | 快拖机会结束；继续等待 300ms 的静止长按。 |
| 到 180ms 已超过 8px，却未在时窗内达到 18px | 两项均不触发，按回退规则尽力交还原输入。 |
| 未命中快拖、也未达到长按阈值就松开 | 尽力补发原右键按下与释放。 |

快拖时窗是严格上界：恰好在 `180ms` 才达到距离，不能命中快速拖拽。到期后不会重新计时或因随后移动而恢复快拖机会。其他按键、滚轮、前台切换、暂停、录制及替换配置会按既有取消协议处理，已消费的释放仍需正确收尾。

快速拖拽只接受鼠标按钮。可配置距离为 **4–500px**，时窗为 **20–2000ms**；距离、时窗、键盘作为拖拽目标分别返回参数错误。同组合的快拖时窗大于或等于长按阈值，会返回时序冲突，指出已有绑定，不静默调整参数。例如 `180ms < 300ms` 可共存，`300ms / 300ms` 会被拒绝。

这项触发会暂存原鼠标按下。未命中时的补发仍可能改变右键菜单出现时间、原生拖动起点与输入时序，不能当作无损恢复；鼠标位移不会被录制后再注入。

## 补发与交付顺序

需要补发的输入由独立后台线程执行 `SendInput`，输入 Hook 不再同步等待该调用。交付队列最多 512 项，按顺序处理离散的按下、释放、滚轮及动作通知，同一时间只有一个输入批次在途。物理鼠标移动直接透传，不进入这个队列，也不通过补发注入鼠标位移。

较早的离散输入需要补发时，后续动作通知会排在它们交付之后；长按保留原始匹配时刻，等待交付的时间仍体现在后续通知耗时中。排队不代表长按会重新计时，也不代表动作业务已完成。

各轮物理按压使用独立编号，旧批次回执只结算对应轮次。队满或补发失败时暂停监听；交付前窗口改变时取消尚未交付的普通输入。已交付按下对应的释放义务会单独保留，避免与普通待发输入一起丢弃。释放清理失败时会显示错误，并允许新普通输入继续通过，避免恢复入口被永久困在失效队列中。

退出收尾会检查待交付、在途及释放清理状态。已经进入原生调用的 `SendInput` 无法取消，最后的释放仍属于尽力收尾；不能承诺完全无损或所有输入都已恢复。旧补发线程尚未结束时，重建监听会明确拒绝并提示稍后重试。

## 区分未触发与显示较慢

偶尔需要重新长按，或感觉等待超过阈值时，可以打开“输入诊断”查看最近一次结果与取消计数。页面每秒更新，提供以下统计：

| 项目 | 含义 |
| --- | --- |
| 最近长按判定 | 最近一次长按结束时的经过时间与配置阈值；成功匹配时显示超出阈值的毫秒数，以及本次运行观测到的最大超出量。提前松开或取消不记为迟到。 |
| 上次长按至面板提交 | 最近一次长按成功呼出面板，从按下到原生显示及激活请求返回的总耗时，同时显示本次运行观测到的最长耗时。长按取消时不会更新最近一次耗时。 |
| 判定后的界面耗时 | 分为“通知”和“显示”：通知是判定完成到界面收到计时通知；显示包括后续界面调度、显示与激活请求。两项相加为判定后的耗时。 |
| 长按命中 / 移动取消 / 切窗取消 / 短按与其他取消 | 用于区分已达到阈值和候选被取消；“其他”还包括额外输入、暂停、录制、替换绑定及错误恢复。 |

“最近 8 次长按结果”只列出已经开始计时的操作，最新结果在前；每项显示经过时间 / 配置阈值。结果分为已命中、未满阈值松开、移动取消、切窗取消、其他按键打断、滚轮打断、配置变更取消、暂停取消、录制取消、恢复或错误取消。

同一区域还统计当前已注册长按目标的物理按下 / 释放、开始计时、未开始与重复鼠标按下次数。重复鼠标按下是尚未收到释放时又收到 Down，单独统计；键盘自动重复不计入该项。“最近未开始原因”概括为监听暂停、正在录制、其他按键仍按住、已有该键按压尚未释放或组合未匹配；没有开始计时的操作不会出现在最近八次结果中。

“面板显示与收起”区分界面呼出请求、原生显示提交、跳过及失败，并统计面板呈现请求、收起和其中的失焦收起；“最近显示”和“最近面板事件”说明最近走到的阶段。原生提交只表示显示调用成功返回。

“Hook 墙钟耗时最大值”将时间分成三个观察项：

| 区间 | 含义 |
| --- | --- |
| 本体 | 本项目 Hook 处理的墙钟耗时，不包含独立线程中的后台补发。 |
| 下游链 | `CallNextHookEx` 调用区间的墙钟耗时。 |
| 后台补发 | 独立补发线程中 `SendInput` 调用区间的墙钟耗时。 |

每项同时显示最大值与慢调用次数，严格超过 `50ms` 才增加慢计数。这些是包括线程被抢占等待在内的墙钟时间，不是 CPU 计时。出现蜂鸣、鼠标短暂停顿或未触发时，可以结合分段耗时和长按结果摘要观察；不能只凭症状或某一最大值认定唯一根因，也不能据此认定卡顿已完全解决。

如果未开始或取消计数增加，先结合原因与对应取消规则检查操作；如果长按已命中，再比较判定经过时间、后续界面耗时与面板显示统计。最近判定与上次面板提交可能来自不同次操作，应结合计数阅读。

面板显示调用在当前界面更新结束后提交，以避免同步窗口消息重入正在更新的界面。激活采用原生 `SetForegroundWindow`，确认取得前台后才调用 `SetFocus`；绕过 GPUI 的 Alt 模拟，不使用模拟按键或 `AttachThreadInput`。系统拒绝激活时仍可点击已显示的面板，物理窗外点击 / `Esc` 通知补足收起。已在前台的面板收到窗外右键长按起始按下时保持显示，避免先隐藏导致前台切换、取消长按；达到阈值再重新定位。

默认长按阈值仍为 `300ms`，移动容差仍为 `8px`。统计用于定位等待发生在哪个阶段，不能仅凭体感或其中一项就确定具体原因。

这些耗时、计数及最多八项结果摘要只保留在本次运行的内存中，不记录任意原始按键或鼠标坐标历史。“面板提交”总耗时计至原生显示及激活请求返回，不等于屏幕像素真正亮起的时刻，也不包含完整的显示器扫描输出。计时与显示调整不能保证恰好 300ms 可见，也不能据此认定所有未触发情况已经排除。

## 可声明、复用的配置

预设、录制、保存和运行共享 `TriggerSpec`。长按配置通过 `activation.kind = "hold"` 表达，按钮与毫秒阈值放在 `value` 中。下面是一份完整的版本 7 配置，只有“右键长按 300ms 打开面板”这一条绑定：

```json
{
  "version": 7,
  "bindings": [
    {
      "id": 1,
      "held": [],
      "activation": {
        "kind": "hold",
        "value": {
          "button": { "kind": "right" },
          "duration_ms": 300
        }
      },
      "message": "打开触发面板",
      "enabled": true,
      "action": { "kind": "show_panel" }
    }
  ]
}
```

`held` 表示目标按钮按下前需要保持的前缀集合；示例为空，因此直接按住右键即可。`action.kind = "show_panel"` 表示面板控制动作，一条绑定只使用一种动作类型。

快速拖拽以独立的 `drag` 触发描述表达，动作字段保持原有结构；版本 5 的已有快拖配置仍可读取，当前保存为版本 7。例如以下触发字段可配合提示、发送快捷键、系统调节、程序、插件或轮盘动作：

```json
"activation": {
  "kind": "drag",
  "value": {
    "button": { "kind": "right" },
    "min_distance_px": 18,
    "max_start_ms": 180
  }
}
```

这类结构可以作为可复用的声明式定义，也能由程序生成；载入时仍会检查时长、组合、位置条件及冲突。当前读取兼容版本 1–7，保存使用版本 7；版本 6 引入位置条件与系统调节动作，版本 7 引入内部版本为 1 的本地步骤动作。首次保存旧配置前创建带旧版本号的备份。已有配置建议通过界面添加预设，保持原有绑定；独立配置试用入口见 [触发面板说明](TRIGGER_PANEL.md)。

## 当前支持范围

当前支持普通按键 / 鼠标按钮按下组合、滚轮方向组合、长按及鼠标快速拖拽；每条可附加一个统一鼠标区域条件。双击、多击、顺序连击和任意 JavaScript 编写的触发条件尚未实现。

脚本用于动作执行，例如调用 RaiShot 或外部解释器；输入 Hook 的同步路径只做有界匹配，不运行脚本。示例与执行边界见 [运行程序与简单脚本](COMMAND_ACTIONS.md)。
