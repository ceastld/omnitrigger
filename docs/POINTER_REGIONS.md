# 鼠标区域条件与音量、亮度调节

鼠标位置是统一的触发条件，和触发方式、执行动作分别配置。例如同一个“左侧边缘”条件可以组合滚轮、按键、鼠标点击、长按或快速拖拽，再分别选择提示、发送快捷键或系统调节动作。

`TriggerSpec.conditions` 保存条件列表，当前最多支持一个 `PointerRegion` 条件；列表为空表示不限位置。录制、配置读取、注册冲突检查与运行时匹配共用核心模型，不为“边缘滚轮”另建一套输入解释。

## 在界面配置

1. 在“触发预设”的“屏幕区域”组选择四条边或四个角落之一。预设使用滚轮上滚，保存前可以切换为下滚、左滚、右滚，或重新录制其他按键组合。
2. 在触发器详情的“鼠标位置条件”里调整区域，选择“不限位置”、八种边角之一或“自定义范围”。已有位置条件在重新录制组合时保留。
3. 选择动作并保存。需要滚轮双向控制时，分别保存上滚和下滚两条绑定；例如上滚增加音量、下滚减少音量。

预设只填写草稿，不自动注册，也不改变已有绑定或系统音量、亮度。条件可与当前普通按下、长按及快拖组合；按键集合仍要求精确匹配，不会忽略额外按住的键。

| 区域 | 默认参数 | 可配置范围 |
| --- | --- | --- |
| 顶部、右侧、底部、左侧边缘 | 厚度 8px | 1–256 个物理像素 |
| 左上、右上、右下、左下角 | 边长 32px | 1–1024 个物理像素 |
| 自定义范围 | 左、上、右、下坐标 | `i32` 物理屏幕坐标；宽高均大于零 |

边角参数表示最大范围。边缘不会越过与相反边的中线；角落不会越过对应的半屏象限。极窄屏幕或较大参数下，中心像素等距时固定归左侧、上侧，保证左右、上下和不同角落互斥，不依赖绑定的先后顺序。自定义矩形包含左、上边界，不包含右、下边界，支持负坐标。

## 多屏与外露边界

屏幕边角使用各显示器完整的 `rcMonitor` 物理矩形，而不是扣除任务栏后的工作区。任务栏本身不会把屏幕边缘向内移；不同缩放的屏幕也不把物理像素参数当成界面逻辑像素。

边缘条件只在外露的边段生效。两块屏幕上下或左右相接时，连接处的共享边段不触发；一条边只部分连接另一屏时，仅排除连接的那一段，保留其余外露部分。屏幕矩形重叠时，落在另一显示器内部的边界也被排除；镜像矩形不重复触发。

角落要求其相邻两条边在角点以及当前鼠标投影处均外露。仅在对角相接的屏幕也会使该连接角失效，避免把跨屏连接点当成外露角落。单个自定义矩形按配置的绝对坐标匹配，不自动扣除多屏连接处。

核心只使用平台显式提供的物理鼠标位置与屏幕矩形，不读取全局状态。位置未知时区域条件不匹配；屏幕信息未知时屏幕边角不匹配，自定义矩形仍可按已知位置判断。平台在监听启动时取得屏幕快照，并在显示拓扑变化后刷新；低级输入 Hook 内不枚举显示器或访问设备。

## 冲突、滚轮与取消

同一按键组合和触发方式下，位置条件有相交可能时会返回结构化冲突，不暗设优先级。左右边缘、上下边缘及不同角落可以分别绑定同一滚轮方向；顶部边缘与左上角会相交，因此相同组合不能同时占用。自定义矩形之间按实际矩形相交判断；自定义矩形与屏幕边角无法在未知屏幕布局下证明互斥时，保守报告冲突。无位置限制的同组合也会与区域绑定冲突。

滚轮按 Windows 标准的 120 增量累计一格，上下和左右方向分别累计。离开区域、进入跨屏连接处或切换到另一绑定的区域时，旧的未满格增量不会借给新绑定。尚未触发的正常高精度增量会按已有补发协议尽力交还前台，即使没有按住前缀键也会处理；例如左边缘已有 60 增量，移到右边缘后，右侧仍需自己的完整一格。

区域失效会取消尚未命中的长按、快拖候选，活动拖拽会收到取消阶段。已经被消费的按下仍拥有对应释放，不能因移出区域而让原按压的释放泄漏。鼠标在区域外按下并已透传的前缀，移入后不会被借作已消费的组合前缀。

屏幕拓扑实际变化会取消旧上下文并消费必要的后续释放，旧缓冲不会补发到新布局；相同的屏幕快照不重复取消。暂停、前台切换、替换绑定和录制继续遵守原有取消规则。自身及其他软件注入的输入不参与匹配，也不推进物理输入状态。

补发会改变输入时序，不能当成无损恢复。单次公共输入最多产生 64 个滚轮命中；异常极大输入的补发保持有界，不保证完整重现所有增量。正常滚轮的未满格余量不跨区域累计。

## 系统调节动作

动作类型“系统调节”提供音量增加、音量减少、亮度增加和亮度减少。每次触发的幅度为 1–100 个百分点，配置用正数表示增加、负数表示减少，不能为零。例如 `+5` 表示从 30% 调到 35%，结果限制在设备支持的范围内。

| 动作 | 目标与方法 |
| --- | --- |
| 音量 | Windows Core Audio 的系统默认多媒体输出端点，不模拟音量键。 |
| 亮度 | 触发时冻结的鼠标位置所在显示器；先使用硬件 DDC/CI，适用时使用通过 DisplayConfig 精确匹配到同一内屏的 WMI 背光接口。 |

亮度操作不会把不支持的外屏请求转到主屏，也不通过修改 gamma 或软件蒙层假装改变背光。不支持硬件控制、目标无法唯一匹配、设备拒绝请求或无法确认结果时会报告原因。DDC/CI 还依赖显示器、连接方式、驱动以及显示器菜单中的相应设置；不承诺所有屏幕可调。

系统调节由音量、亮度各自的固定后台线程处理，设备查询和写入不进入 Hook 或界面同步路径，慢亮度接口也不阻塞音量和普通快捷键。两类动作共用 8 个待执行、运行中与未读结果配额。同一绑定尚未开始的连续同向请求可合并为总百分点，亮度还要求冻结的物理点完全相同；反方向、不同绑定或不同亮度目标点不会跨批合并。界面反馈使用原生接口读回的值；成功提交不等于硬件已经达到请求值，读回失败会明确报告确认状态，而不是显示虚假的成功数值。

Windows 适配还提供 `adjust_system_at(action, point)` 和只读的 `query_system_adjustment_capabilities_at(point)` 方法。调用方应在工作线程运行，并传入触发时冻结的物理点；查询能力不会改变音量或亮度。本项目自动测试不通过写入真实音量、亮度来验证设备支持。

## 配置与试用

绑定文件当前保存为版本 7，读取兼容版本 1–7。版本 6 引入位置条件与系统调节动作，`conditions` 可省略或为空；版本 1–5 不支持非空位置条件或系统调节动作。版本 7 新增本地步骤动作，其动作内部版本为 1。首次保存旧配置会先创建带原版本号的备份，失败时不覆盖原文件。

以下是一条左边缘上滚调高音量的绑定：

```json
{
  "id": 1,
  "held": [],
  "activation": { "kind": "wheel_up" },
  "conditions": [
    { "kind": "pointer_region", "region": { "kind": "screen_edge", "edge": "left", "thickness_px": 8 } }
  ],
  "message": "左边缘上滚增加音量",
  "enabled": true,
  "action": { "kind": "adjust_system", "target": "volume", "delta_percent": 5 }
}
```

角落与矩形条件分别使用以下形态：

```json
{ "kind": "pointer_region", "region": { "kind": "screen_corner", "corner": "top_left", "size_px": 32 } }
```

```json
{ "kind": "pointer_region", "region": { "kind": "rectangle", "left": -200, "top": 0, "right": 0, "bottom": 200 } }
```

`edge` 为 `top`、`right`、`bottom`、`left`；`corner` 为 `top_left`、`top_right`、`bottom_right`、`bottom_left`。区域条件不会修改 `activation`，也不把调节动作绑定死在滚轮上。

完整示例 [screen-edge-adjustments.json](../examples/screen-edge-adjustments.json) 提供四条绑定：左边缘上、下滚调节音量，右边缘上、下滚调节对应屏幕亮度，每格 5 个百分点。该文件不是默认启用映射，不会自动写入用户配置。构建程序后可先检查，再复制到独立目录试用：

```powershell
.\target\debug\omnitrigger.exe --config .\examples\screen-edge-adjustments.json --check-config
New-Item -ItemType Directory -Force .\.local\screen-edge-demo
Copy-Item .\examples\screen-edge-adjustments.json .\.local\screen-edge-demo\bindings.json
.\target\debug\omnitrigger.exe --config .\.local\screen-edge-demo\bindings.json
```

`--check-config` 只校验格式、参数与冲突，不安装 Hook 或调节硬件。使用试用配置后，真实滚轮命中会执行对应设备操作。

## 单独调用调节方法

以下命令不创建界面，也不安装 Hook。能力检查只读取设备信息；两个调节命令会真实写入音量或亮度。

```powershell
.\target\debug\omnitrigger.exe --check-system-controls
.\target\debug\omnitrigger.exe --check-system-controls --point "-100,200"
.\target\debug\omnitrigger.exe --adjust-volume 5
.\target\debug\omnitrigger.exe --adjust-volume -5
.\target\debug\omnitrigger.exe --adjust-brightness 5 --point "100,100"
```

未提供 `--point` 时读取当前物理鼠标位置；提供时使用 `x,y` 物理坐标选择亮度目标屏幕。调节幅度为 -100 至 100 的非零百分点。能力输出分别包含音量、亮度是否可用、当前值、目标与不支持原因；能力可用不能保证之后设备状态不变。系统命令不与 `--check-config`、`--smoke-test` 或界面启动参数混用。
