# OmniTrig

统一录制、注册与管理键盘和鼠标组合的 Rust 触发引擎。

目标是让用户录下一个操作，就能将其注册为触发器，例如 `CapsLock + W`、`鼠标侧键 + 滚轮上滚`。触发器的绑定、分配与动作协调通过 API 交给代码或 Agent，减少重复的人类配置。

## 当前状态

首版 Windows 测试程序使用 Rust + GPUI，提供全局键盘/鼠标组合监听、录制、注册和提示浮层。核心与界面独立，不依赖其他产品代码。

当前可测试：

- 预置 `CapsLock + W`、`鼠标侧键 1 + 滚轮上滚/下滚`。
- 点击“开始录制”，按住前缀，再按目标键或滚动滚轮，全部松开后完成录制；`Esc` 取消。
- 输入提示文字，点击“添加触发器”；同一份触发器描述用于录制结果、注册验证和运行时匹配。
- 触发后在屏幕右下角显示 4 秒提示，并记录命中；提示浮层不激活窗口。
- 编辑消息、预览提示、启用/停用、删除，以及暂停全部监听。
- 自动保存到 `%LOCALAPPDATA%\OmniTrig\bindings.json`。初次运行加载示例，之后保留用户配置。

“测试提示”只验证消息显示，真实输入触发会单独累计命中次数。程序退出后移除监听。

## 启动与验证

需要 Windows、Rust 1.90+（MSVC 工具链）及 Visual Studio C++ Build Tools。

```powershell
.\start.ps1                       # 构建并打开界面
cargo run -p omnitrig-app          # 在终端运行
cargo test --workspace
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo run -p omnitrig-windows --example hook_smoke  # 真实 Hook 安装/卸载检查
```

直接启动产物：`target\debug\omnitrig.exe`。

测试建议：先按住 `CapsLock` 再按 `W`，松开后确认提示和命中次数；然后测试侧键加滚轮，最后录制一个自定义组合。单独按下并松开未被组合使用的前缀时，会回放原输入。

## 与 ScriptDesk 的关系

当前提示由 OmniTrig 自身显示。ScriptDesk 已有脚本内的 `api.notify(message, title?)`，但尚无面向外部应用的通知调用入口，本版不改变 ScriptDesk。后续可通过动作适配接口连接脚本执行与通知能力。

## 与其他输入工具并用

Windows 的同类低级 Hook 按后安装在前的顺序处理。其他软件若在上游拦截 CapsLock、侧键或滚轮，OmniTrig 就可能收不到原输入；上游补发的模拟输入仍按原策略过滤，避免动作自触发。仅凭漏触发不能认定具体来源。

- 底部诊断每秒更新键盘/鼠标回调数、模拟输入数及当前按住状态。
- 偶发失效时，松开其他按键后点击“重建监听”：旧监听先按原释放协议收尾，再启动新输入线程、重新安装 Hook，并恢复绑定及暂停状态；清除旧线程残留的按键状态。保留消息、录制结果和用户配置。
- 程序不定时重装 Hook 抢链首；其他软件稍后再次重装时，仍可能改变输入顺序。
- 输入线程结束或重建失败时明确显示未监听，不再维持“正在监听”的假状态。

可控优先级检查：`cargo run -p omnitrig-windows --example hook_priority_smoke`。测试 Hook 仅拦截专用标记的 F24 模拟探针，验证上游吞事件及重建后顺序变化；不改变其他应用，也不将探针交给前台窗口。

## 核心设计

- **统一描述**：录制器生成 `TriggerSpec`，注册、冲突检查与运行时匹配共享这一份语义。
- **确定性状态机**：核心按 `InputEvent → Engine::process → Decision` 工作，输入标准化事件，输出透传、消费、触发通知及必要的补发计划。核心不依赖 UI 或 Windows API。
- **平台适配**：Windows 适配层负责采集输入、执行消费决策和补发；系统 Hook 的同步路径只做有界匹配，不执行动作、网络请求或 Agent 推理。
- **程序化协调**：通过 API 管理触发器与动作标识，动作执行与自动分配由调用方协调。冲突应返回结构化诊断，避免静默改变录制结果。
- **轻量界面**：GPUI 作为候选界面，负责录制、展示、编辑与必要确认，与核心引擎解耦。

## 输入语义边界

“任意组合”是模型的扩展目标，实际能力受系统与硬件提供的事件约束。

已注册的前缀按下时暂存输入，组合命中后消费整次按压；遇到不匹配输入或单独松开时回放。延迟与补发会改变时序，不能承诺完全无损。前台窗口切换、暂停或替换注册列表时取消旧缓冲，避免向新窗口补发旧输入。

组合使用精确按下集合，区分左右修饰键；键盘长按默认只触发一次。滚轮以 Windows 标准的 120 增量为一格，高精度增量累积，正反方向分别统计。自身补发和其他软件注入不触发，也不参与录制。

本版只支持“按住若干键 + 按下一键/滚轮方向”的单步组合，最多 64 条绑定、每条最多 8 个前缀；重复组合和终端键同时被其他组合用作前缀时会返回冲突。界面不允许把单独的鼠标左/右键设为全局触发器，以保留界面操作能力。暂不支持顺序连击、长按计时或按设备区分；Windows 安全桌面和系统保留组合仍受系统限制。

普通权限运行；向权限更高的应用补发输入可能失败，此时暂停监听并显示错误。无需安装驱动。

## 工程结构

- `crates/omnitrig-core`：无外部依赖的事件模型、注册验证、状态机与录制器。
- `crates/omnitrig-windows`：专用消息线程、低级输入 Hook、消费/补发和生命周期。
- `crates/omnitrig-app`：GPUI 管理界面、中文消息输入、配置和提示浮层。
