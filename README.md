# OmniTrigger

统一录制、注册与管理键盘和鼠标组合的 Rust 触发引擎。

录下一个操作，就能将其注册为触发器，例如 `CapsLock + W`、`鼠标侧键 + 滚轮上滚`。当前提供 Windows 桌面测试程序，触发后显示本地提示、发送快捷键、运行程序或脚本，也可呼出自定义动作轮盘；还可在动作库安装 RaiShot 插件，选择截图动作并设置触发。

项目处于 `0.1.0` 早期开发阶段，API 与配置格式可能调整。目前仅支持 Windows，不提供稳定版本或自动更新。

[源码仓库](https://github.com/ceastld/omnitrigger) · [贡献指南](CONTRIBUTING.md) · [安全说明](SECURITY.md) · [MIT 许可证](LICENSE)

## 当前状态

首版 Windows 测试程序使用 Rust + GPUI，提供全局键盘/鼠标组合与长按监听、预设、录制、注册、浮动面板和自定义轮盘。核心与界面独立，不依赖其他产品代码。

界面为深色霓虹风格：薄荷到天青的渐变强调色、带光晕的立体键帽，并按动作类型着色区分。左侧栏包含监听状态卡、浮动触发面板入口（显示当前呼出组合）、呼出组合录制和“动作库 / 轨道轮盘 / 触发预设 / 触发器 / 触发记录 / 输入诊断”页面切换。触发器页上方为统计胶囊，中间为触发器列表，每行带动作类型图标、组合键帽与命中次数；右侧为悬浮详情卡，包含组合展示区、“按下即触发 / 长按触发”分段切换、动作类型选择格，底部固定保存、测试与删除按钮。底部状态栏显示监听状态与输入计数。

界面延伸到标题栏：侧栏与各页面底色直达窗口顶部，应用名所在行和页面顶部空白处可拖动窗口；右上角保留系统原生的最小化、最大化、关闭按钮（含悬停效果与 Windows 11 贴靠布局）。程序图标为键帽加闪电，已嵌入 `omnitrigger.exe`，用于窗口、任务栏与资源管理器。若标题栏接管失败，界面提示错误并改用系统标题栏。

当前可测试：

- 预置 `CapsLock + W`、`鼠标侧键 1 + 滚轮上滚/下滚`，组合以键帽形式显示，鼠标按键带图标、滚轮带方向箭头。
- 新配置预置 `CapsLock + Space` 切换浮动触发面板的显示状态，右键长按 `300ms` 每次在当前鼠标位置显示面板，已打开时重新定位。面板以鼠标位置为中心显示三列动作卡片，高度随行数变化，不移动鼠标，靠近屏幕边缘时调整位置以保留在工作区内。面板是无焦点浮窗，不抢占前台，原窗口保持输入焦点；面板可见时，输入采集只接管单独按下的方向键、`1`–`9`、`Esc`，以及方向键选择后的 `Enter`。点击筛选框后面板才取得前台并接收文字筛选，收起时交还前台。底部说明栏显示悬停或选中动作的组合与状态。点击或按键运行后先收起再执行。`Esc`、点击面板以外的位置或关闭按钮均可收起。停用、执行中或未就绪的动作不可运行，打开面板的绑定不作为卡片显示。
- 面板启动时预创建并保持隐藏，之后复用同一窗口及图形资源；触发通知直接唤醒界面，不等待维护轮询。长按阈值保持用户配置的数值，显示仍受系统调度与屏幕刷新影响。
- 面板以不激活方式显示，不模拟 Alt 等按键；靠物理外部点击与 `Esc` 收起。点击筛选框时才使用原生前台请求，系统未授予焦点时仍可点击动作。“输入诊断”还提供 Hook 本体、下游 Hook 链和补发的最大墙钟耗时及慢调用次数。
- 输入补发由独立线程执行，Hook 回调只做有界匹配与排队；等待补发时按顺序交付后续离散输入，鼠标移动继续透传，不重放位移。交付失败或队列满时暂停监听并尽力完成必要的释放；这仍不能保证无损恢复。
- Windows 长按优先使用一次性高精度等待计时器，消息持续到来时也检查到期时间；系统不支持时依次回退普通等待计时器、`SetTimer`。“输入诊断”显示实际计时方式、长按判定和面板提交耗时，以及移动、切窗和其他取消次数。
- “触发预设”提供 14 个可编辑模板，包括右键 / 中键 / 侧键长按、键盘长按和常用键鼠组合。选择预设会保留当前动作，确认参数并保存才会生效；也可将录制结果切换为长按，填写 `50–10000ms`。普通按下与同一组合的长按、同一组合的多个长按阈值会明确报告冲突。详见[预设与长按说明](docs/TRIGGER_PRESETS.md)。
- 左侧“打开触发面板”可直接试用；“录制面板呼出组合”可录制键盘或鼠标组合，保存后生效。旧配置保持原有绑定，不自动添加组合，使用侧栏入口录制即可。详见[浮动面板说明](docs/TRIGGER_PANEL.md)。
- “轨道轮盘”页可创建多个命名轮盘，选择三种配色，配置 1–8 个独立动作槽位并调整顺序。支持发送快捷键或复制已有普通动作；默认“编辑轨道”包含复制、粘贴、全选和撤销。设置呼出组合会生成 `CapsLock + Tab` 草稿，保存且通过冲突检查后才注册。运行时移向槽位并左击，或用数字键及方向键加 `Enter` 确认；中心安全区和圈外不执行，`Esc`、外部点击、切窗、暂停或录制会取消。轮盘不抢焦点、不移动鼠标。详见[自定义轮盘](docs/RADIAL_WHEELS.md)。
- 点击“录制组合”，按住前缀，再按目标键或滚动滚轮，全部松开后完成录制；录制期间实时显示已按住的键，`Esc` 取消。录制会拦截全部输入，鼠标点击也会被录下。
- 录完立即按注册规则检查：与已有组合重复、目标键与其他组合的前缀冲突、单独左/右键按下等情况会指出冲突的触发器，可查看或重新录制，不覆盖原有绑定。单独左/右键可以选择长按方式后再注册。
- 填写提示消息后点击“添加触发器”；同一份触发器描述用于录制结果、注册验证和运行时匹配。
- “仅提示”动作在屏幕右下角显示 4 秒提示，带组合键帽和倒计时条；提示浮层不激活窗口。程序动作直接执行，避免截图时将提示浮层拍入。
- 列表显示每条触发器本次运行的命中次数与最近时间（有命中时显示）；开关可启用/停用，详情卡中编辑消息与动作、测试提示，删除需再次点击确认。
- “动作库”内置 RaiShot 截图动作及默认快捷键 `左 Ctrl + 左 Alt + A`。安装插件会下载截图程序及随包运行库，配置由多个绑定共享；选择“设置触发”只填入草稿，可以自定义组合、选择触发预设或恢复默认，保存前检查冲突。
- 动作可选择“发送快捷键”，支持 `Backspace`、方向键、`Ctrl+C`、`Ctrl+Shift+Left` 等单键和组合，每次触发发送一次完整按下与释放。发送在独立后台队列执行，前台窗口切换则取消，自身注入不再次触发。配置和 CapsLock 导航示例见[发送按键与快捷键](docs/KEYBOARD_ACTIONS.md)。
- 动作仍可选择“仅提示”“触发面板”或“运行程序”。程序动作填写路径、参数数组及可选工作目录；解释器可用于运行 PowerShell、Node 等脚本。
- “测试动作”真实运行当前草稿中的程序，不必先保存，不计入命中次数。“测试提示”仍只显示文字。外部命令由后台执行，同一绑定运行期间拒绝重复启动，总计最多 4 个任务；启动失败、非零退出码和忙碌拒绝会显示在界面与动作执行记录中。
- 侧栏可暂停/恢复全部监听；暂停或监听断开时列表变暗并显示提示条。
- “触发记录”保留本次运行最近 30 条，可按组合触发、面板点击与测试提示筛选；面板点击单独计数，不计入组合命中次数。
- 自动保存到 `%LOCALAPPDATA%\OmniTrigger\bindings.json`。初次运行加载示例，之后保留用户配置。

“测试提示”只验证消息显示，不计入命中次数；命中统计与记录只在本次运行期间保留。提示消息输入框为单行。程序退出后移除监听。

## 使用 RaiShot 截图插件

1. 打开侧栏“动作库”，点击“安装 RaiShot 插件”。程序在后台下载并校验固定版本 `0.4.15` 的原发布包，安装完成后保存共享 CLI 路径。安装本身不启动截图，也不注册快捷键。
2. 在截图卡片点击“设置触发”，默认填入 `左 Ctrl + 左 Alt + A`。这是 OmniTrigger 适配提供的默认组合，可点击“重新录制”录制自己的组合，或“选择预设”改用长按、侧键等方式。
3. 点击“添加触发器”；编辑已有绑定时点击“保存动作”。“恢复默认”只修改当前草稿，仍需保存并通过冲突检查，不覆盖其他组合。
4. 使用组合触发截图，或从浮动面板点击动作。“测试截图动作”会真实启动截图；进程正常退出也可能是取消截图，不能据此认定已经生成图片。

已有 RaiShot 时，可填写 `raishot-cli.exe` 的完整路径后点击“保存并启用”，无需重新下载。动作库也提供刷新和停用；缺失程序、停用插件或不兼容动作会保留绑定并标记不可用，同时移出实际监听注册集。多个截图绑定与测试入口共享单并发，忙碌时拒绝新调用。

安装器访问 [RaiShot v0.4.15 发布包](https://github.com/ceastld/raishot/releases/tag/v0.4.15)，先尝试匿名 HTTPS。当前下载仓库需要访问权限；匿名下载不可用时，安装器尝试使用本机已安装、已登录且有仓库权限的 GitHub CLI（`gh`），不会自动安装或登录 `gh`。无权限时显示安装错误；也可使用自己已安装的程序路径。

下载包包含截图所需程序、DLL 和许可文件；安装器校验 ZIP 的 SHA-256 及包内文件后再启用，失败保留原设置，不自动重试。运行文件位于配置文件同级的 `plugins\raishot\runtime\0.4.15`。RaiShot 保留其 GPL-3.0-or-later 及随包第三方许可，详见[第三方说明](THIRD_PARTY_NOTICES.md)。当前不支持外部插件清单导入、插件市场或自动更新，Clip 尚未接入。

## 启动与验证

需要 Windows、Rust 1.90+（MSVC 工具链）及 Visual Studio C++ Build Tools（含“使用 C++ 的桌面开发”和 Windows SDK）。建议在 PowerShell 7 中执行：

```powershell
git clone https://github.com/ceastld/omnitrigger.git
cd omnitrigger
.\start.ps1                                      # 构建并打开界面
cargo run -p omnitrigger-app --locked             # 在终端运行
```

构建和检查：

```powershell
cargo build -p omnitrigger-app --locked
cargo test --workspace --locked
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
```

真实 Hook 检查需要交互式 Windows 桌面，CI 不覆盖实际按键、输入焦点或权限差异：

```powershell
.\target\debug\omnitrigger.exe --smoke-test
cargo run -p omnitrigger-windows --locked --example hook_smoke
```

直接启动产物：`target\debug\omnitrigger.exe`。

也可通过 `--config <文件路径>` 使用独立配置，例如 `.\target\debug\omnitrigger.exe --config .\.local\demo\bindings.json`；后续编辑会保存到该文件，适合隔离试用。

使用 `--check-config` 可检查所选配置的格式、动作参数、组合冲突、同目录轮盘配置及轮盘引用，不安装 Hook 或执行动作：`.\target\debug\omnitrigger.exe --config .\examples\capslock-navigation.json --check-config`。

轮盘管理和显示入口：

```powershell
.\target\debug\omnitrigger.exe --wheel-editor
.\target\debug\omnitrigger.exe --wheel orbit-edit  # 显示指定轮盘，等待选择
```

两个入口均可配合 `--config` 使用；轮盘编辑与呼出组合设置见[自定义轮盘](docs/RADIAL_WHEELS.md)。

测试建议：先按住 `CapsLock` 再按 `W`，松开后确认提示浮层和列表中的命中次数；然后测试侧键加滚轮，最后录制一个自定义组合。单独按下并松开未被组合使用的前缀时，会回放原输入。

## 配置与隐私

启动时加 `--panel` 可直接显示浮动面板；可以同时指定 `--config` 使用独立配置。主窗口负责配置管理，关闭主窗口会退出应用；当前没有系统托盘。

绑定、提示文字与动作参数保存在 `%LOCALAPPDATA%\OmniTrigger\bindings.json`；没有 `LOCALAPPDATA` 时使用系统临时目录下的 `OmniTrigger\bindings.json`。读取兼容版本 1–4，保存使用版本 5；首次保存旧配置前创建 `bindings.json.v<旧版本>.bak` 备份，备份失败不会覆盖原配置。回退旧程序时需恢复对应备份。

插件启停和共享程序路径保存在绑定文件同级的 `plugins.json`。使用 `--config` 时，插件设置和下载目录也位于所选配置文件的目录，便于隔离试用。旧程序动作保持原始参数，不自动转换成插件引用。

轮盘内容保存在绑定文件同级的 `wheels.json`，使用版本 1；呼出组合在版本 5 绑定中保存 `show_wheel` 动作与轮盘标识。每个槽位独立保存动作参数，不随复制来源的绑定更改。轮盘引用缺失时保留绑定并标记不可用；损坏或不支持的轮盘配置不会被保存操作覆盖，保存失败时保留原文件。

程序与参数逐项传递，不默认经过 Shell，不展开环境变量或引号，也不自动重试。外部程序按当前用户权限运行；仅启动自己信任的程序和脚本。进程正常退出不代表插件业务已完成，标准输出与错误输出当前不采集。暂停监听只阻止新触发，退出 OmniTrigger 不会终止已启动的外部程序。见[外部动作与脚本示例](docs/COMMAND_ACTIONS.md)。

当前应用不提供遥测、云同步或输入上传。插件安装会访问 GitHub 下载程序及运行依赖，不上传输入事件或截图；全局监听用于本机匹配与录制，触发记录和输入诊断仅保留在进程内。配置中的提示文字、诊断截图可能包含个人内容，报告问题前请自行脱敏。

## 与其他输入工具并用

Windows 的同类低级 Hook 按后安装在前的顺序处理。其他软件若在上游拦截 CapsLock、侧键或滚轮，OmniTrigger 就可能收不到原输入；上游补发的模拟输入仍按原策略过滤，避免动作自触发。仅凭漏触发不能认定具体来源。

- “输入诊断”页每秒更新键盘/鼠标回调数、最近事件时间、外部模拟输入数、当前按住的键，以及自身补发、切换窗口取消和补发失败次数；底部状态栏显示简要计数。
- 长按诊断显示实际判定耗时、配置阈值、判定后的通知与显示提交耗时，并分别累计移动、切窗与短按 / 其他取消。可据此区分超时显示与候选被取消；数据只在内存保存，显示提交耗时不等于显示器像素亮起的时刻。
- 偶发失效时，松开其他按键后点击“重建监听”：旧监听先按原释放协议收尾，再启动新输入线程、重新安装 Hook，并恢复绑定及暂停状态；清除旧线程残留的按键状态。保留消息、录制结果和用户配置。
- 程序不定时重装 Hook 抢链首；其他软件稍后再次重装时，仍可能改变输入顺序。
- 输入线程结束或重建失败时明确显示未监听，不再维持“正在监听”的假状态。

可控优先级检查：`cargo run -p omnitrigger-windows --locked --example hook_priority_smoke`。测试 Hook 仅拦截专用标记的 F24 模拟探针，验证上游吞事件及重建后顺序变化；不改变其他应用，也不将探针交给前台窗口。

## 核心设计

- **统一描述**：录制器生成 `TriggerSpec`，注册、冲突检查与运行时匹配共享这一份语义。
- **确定性状态机**：核心按 `InputEvent + 显式时间 → Engine::process_at / advance_time → Decision` 工作，输入标准化事件和单调毫秒时间，输出透传、消费、触发通知及必要的补发计划。核心不读取系统时钟，不依赖 UI 或 Windows API；原 `process` 接口沿用最近显式时间。
- **平台适配**：Windows 适配层负责采集输入、执行消费决策和补发；系统 Hook 的同步路径只做有界匹配，不执行动作、网络请求或 Agent 推理。
- **程序化协调**：当前 Rust 库提供触发器注册与决策接口，冲突返回结构化诊断；桌面程序在 Hook 之外异步执行外部命令。工作流调用协议与自动分配尚未实现。
- **轻量界面**：GPUI 作为候选界面，负责录制、展示、编辑与必要确认，与核心引擎解耦。

插件采用“插件提供预设动作与默认快捷键，OmniTrigger 管理绑定”的方式。当前内置 RaiShot 截图清单，默认组合可自定义、恢复并经过统一冲突检查，执行仍在 Hook 之外。已实现范围与后续清单扩展见[插件动作与快速绑定设计](docs/PLUGIN_SYSTEM.md)；更长期的执行器边界见[执行器与插件架构建议](docs/EXECUTION_ARCHITECTURE.md)。现有 Node 调用示例见[截图脚本](examples/raishot-capture.mjs)。

## 输入语义边界

“任意组合”是模型的扩展目标，实际能力受系统与硬件提供的事件约束。

已注册的前缀按下时暂存输入，组合命中后消费整次按压；遇到不匹配输入或单独松开时回放。延迟与补发会改变时序，不能承诺完全无损。前台窗口切换、暂停或替换注册列表时取消旧缓冲，避免向新窗口补发旧输入。

组合使用精确按下集合，区分左右修饰键；键盘长按默认只触发一次。滚轮以 Windows 标准的 120 增量为一格，高精度增量累积，正反方向分别统计。自身补发和其他软件注入不触发，也不参与录制。

本版支持“按住若干键 + 按下一键/滚轮方向”及目标键长按，最多 64 条绑定、每条最多 8 个前缀。长按阈值为 50–10000ms，同一按压只触发一次；计时不依赖下一次输入。鼠标长按在尚未到时位移超过 8 个物理像素时取消，额外按键或滚轮也会取消等待。右键短按会延后补发，拖动起点和时序可能改变，不能承诺无损恢复；系统计时器和界面调度也会影响面板实际出现时刻。

重复组合、按下与长按争用同一组合、同一组合的多个长按阈值，以及终端键同时被其他组合用作前缀时会返回冲突。界面禁止单独左/右键的“按下即触发”，允许明确设置为长按。暂不支持双击、多击、顺序连击或按设备区分；Windows 安全桌面和系统保留组合仍受系统限制。

普通权限运行；向权限更高的应用补发输入可能失败，此时暂停监听并显示错误。无需安装驱动。

## 工程结构

- `crates/omnitrigger-core`：无外部依赖的事件模型、注册验证、状态机与录制器。
- `crates/omnitrigger-windows`：专用消息线程、低级输入 Hook、消费/补发和生命周期；主窗口标题栏延伸（DWM 窗框与系统按钮命中）。
- `crates/omnitrigger-app`：GPUI 管理界面（主题与键帽组件、内置图标）、中文文本输入、配置与冲突检查、动作库与内置插件清单、依赖下载安装、提示浮层、有界外部命令执行。`assets/` 存放程序图标的 SVG 源稿（大尺寸与 16–24px 简化版）与生成的 `omnitrigger.ico`，构建时经 `build.rs` 嵌入。
