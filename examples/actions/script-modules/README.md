# 多文件脚本工程

入口 `main.mjs` 具名导出同步函数 `main(ctx)`，返回 JSON 值。通过标准 `import` / `export` 拆分代码，无需 npm、Node 或转译。示例仅整理输入并返回结果，不修改文件、剪贴板或窗口。

导入使用 `./` 或 `../` 开头的相对路径，明确写出 `.js` 或 `.mjs` 扩展名。例如 `import { cleanText } from './lib/text.js'`。所有依赖必须位于动作包内；不加载 npm 包、内置 Node 模块、URL、JSON、目录入口或原生库。模块顶层和共享模块不隐式获得 `ctx`，需要从 `main(ctx)` 向辅助函数传入所需参数；工程 SDK 不声明全局 `ctx`。

同一调用内每个规范化文件只初始化一次，支持 ESM 循环导入与实时绑定；循环中提前读取未初始化的绑定会产生 JavaScript 异常。下一次调用创建新进程并重新读取代码，因此保存后下次执行生效。每次最多加载 64 个文件，单文件 128 KiB，总计 1 MiB。不遍历未导入的文件。

`jsconfig.json` 开启所有 `.js` / `.mjs` 的 JS 类型检查；保留入口的 `@type {ScriptMain}` 注释。在支持 JS / TypeScript 的编辑器中打开整个工程即可跨文件补全。应用的“编辑代码”会为 VS Code 打开工程文件夹和入口；其他编辑器的适配见开发文档。SDK 为工程创建时的类型快照，更新程序不会覆盖作者文件。

`call.json` 提供开发调用输入。应用中的“重新加载”用于新增包或修改清单，单纯保存 JS 源码无需重新加载；创建工程不会添加触发绑定。宿主 API 保持同步，入口不能返回 Promise；没有结果时返回 `null`。模块初始化没有外部异步事件循环，无法完成的初始化 Promise 会报 `module_pending`。

原有 `.js` 入口继续使用 `function main(ctx)`，函数体宿主协议继续使用 `script` 字段。要迁移为模块，在清单中将入口改为 `.mjs`，并为主函数添加 `export`。目录加载与“检查动作”只检查清单和运行时，不执行或静态分析模块图；实际运行时才解析并检查每个导入。加载范围限制不是权限沙盒，已有文件和系统 API 仍可能产生不可撤销的副作用。
